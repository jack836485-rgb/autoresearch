### IDEA-001：基准结构评分回归增益保留率（问题卡切口）

- 来源：`问题卡切口`
- 父 Idea：`无`
- 状态：`available`
- 定位关键词：agent benchmark validity；context compaction；harness evolution；held-out generalization
- 一句话背景：agent 评测中，静态基准的结构性质（目标固定、无用户输入、状态可重读、只判终态、搜索集可穷举）可能让方法增益在交互、留出、过程口径下不保留。
- 与起点问题的关系：原问题；照卡片做法给 3–4 个基准打结构分，回归增益保留率。
- 主贡献：一个基准级结构评分及其对跨方法族增益保留率的回归关系。
- 贡献自评：重要性 6.0 / 新颖度 6.0 / 有效性 5.0；待预研：保留率的分布与结构分的相关程度。
- 可行性：pass（但需要在 3–4 个基准上各造多种变体，工作量大）
- 自评分：`5.3/10`
- 一段话概括：按 4 项结构性质给 3–4 个 agent 基准打分，每个基准造"去性质"变体，在压缩、技能、harness 演化三族方法上测增益保留率，回归到结构分。
- Story line：多族方法在静态基准上的增益换口径后消失（2610.31778、HDA、2609.39148）→ 基准结构性质可能是共同原因 → 给基准打分并回归 → 预期结构分越高保留越差。
- 打分理由：回归的自变量是基准级分数，样本只有 3–4 个基准，无法区分"结构性质"与"任务难度、领域"；不同基准上造的变体也会改变难度（卡片已知边界）；同一基准内不同方法保留率不同的现象（HDA 里 Meta-Harness 与 SkillOpt 不同）无法由基准级分数解释。
- Idea 生成依据：来自问题卡 Q026。
- 自评分轻量新意依据：基准效度审计（2605.10448、2607.02577、2507.02825 ABC、2605.20530 AgentAtlas 覆盖度审计）都不预测方法增益保留；需要 reviewer 检索。
- 与输入论文的关系：不适用
- 本 Idea 的独立创新点：把结构性质量化为基准属性并跨族回归。
- Reviewer 记录：`尚未送审`

### IDEA-002：同一任务上的内容保持型结构切换，检验方法机制决定增益是否依赖基准可供性（领域共性不足）

- 来源：`领域共性不足`
- 父 Idea：`IDEA-001`
- 状态：`available`
- 定位关键词：context compaction；harness evolution；SWE-bench Verified；side constraints
- 一句话背景：上下文压缩与 harness/技能演化两族方法在 SWE 类静态基准上的增益，都可能依赖基准提供、而真实使用中不存在的条件（信息可从仓库重读、只按测试通过判分）。
- 与起点问题的关系：子问题；对象仍是方法增益的保留，但把"给基准打结构分"改成在同一批任务上切换结构条件、测方法×条件交互，只覆盖"无用户输入／可重读"和"只判终态"两类性质，不处理"跨多个基准"的部分。
- 主贡献：在同一任务、同一模型上，只改变约束信息所在的通道（仓库文件 vs 运行中的用户消息）和判分口径（只判终态 vs 加过程检查），证明两族方法的增益方向与排序按其机制（丢弃信息／按终态分数拟合）发生可预测的变化，而不是统一打折。
- 贡献自评：重要性 6.5 / 新颖度 6.5 / 有效性 6.5；待预研：各方法在切换后的增益变化幅度。
- 可行性：pass
- 自评分：`6.3/10`
- 一段话概括：在 SWE-bench Verified 的 98 个任务（HDA 的搜索集+测试集）上给每个任务加 3 条带确定性检查器的过程／范围约束，同一内容分别放在仓库规则文件里或在运行中以用户消息给出；两族方法：OpenCode 内的 5 种压缩策略（相对默认自摘要），HDA 发布的 Meta-Harness / SkillOpt 演化产物（相对各自基线 harness）。预先按机制给每个方法标注它是否依赖"可重读"或"只判终态"，检验标注能否预测切换后增益的符号变化，并与"所有方法统一打折"的零假设比较。
- Story line：两族方法都在静态基准上出现增益不保留（2610.31778 压缩丢约束；HDA 留出回退）→ 共同原因假设：基准提供了冗余的恢复或判分通道，掩盖了丢弃信息或按终态拟合造成的损失 → 只切换通道、不改内容 → 预测丢弃信息类与拟合类方法增益变小甚至反号、保留信息类方法增益变大。
- 打分理由：设计比 IDEA-001 干净（内容不变，避开难度混淆），但只回答"静态基准内切换会不会改变方法排序"，没有回答这种切换能否代表真实交互使用；压缩一侧的方向已被 2608.11242、2610.31778 部分说明，跨族部分容易被看成组合。
- Idea 生成依据：2610.31778 §4–5；2608.11242 §2、SC 提取器；HDA SWE-bench 发布产物（演化 harness 提示中已写"Do NOT modify test files"但不计分）；2609.18366 的"增益摧毁"估计量。
- 自评分轻量新意依据：未检出在同一任务上切换信息通道并比较多族方法增益的工作；CHASE 只换协议、只做 harness 族。
- 与输入论文的关系：不适用
- 本 Idea 的独立创新点：内容保持型的"通道切换 + 判分切换"作为跨族的方法增益检验。
- Reviewer 记录：`尚未送审`

### IDEA-003：静态基准上的廉价结构切换能否预测方法增益在真实交互会话中的保留（领域共性不足 + 预测效度）

- 来源：`领域共性不足`
- 父 Idea：`IDEA-002`
- 状态：`needs_revision`（第 1 轮未过，子候选 IDEA-006）
- 定位关键词：context compaction；harness evolution；SWE-bench Verified；SWE-Together；user simulator；side constraints
- 一句话背景：编码 agent 的方法研究（上下文压缩、技能与 harness 演化）用静态基准（如 SWE-bench Verified）选方法，但真实使用是交互式的；已知模型层面静态与交互排序大体一致，方法层面的增益能否迁移、能否事先预测，尚未检验。
- 与起点问题的关系：子问题；保留"方法增益换到交互／过程口径后还剩多少、能否事先预测"这一对象，把"按结构性质给基准打分"改成"在静态基准上做两项结构切换测方法的依赖程度"，并用真实会话重建的交互基准检验预测力；原问题中跨多个基准的结构评分、留出任务族口径（已由 HDA 部分回答）和非编码领域仍未回答。
- 主贡献：若成立，得到一个方法层面的"迁移预测"结论与工具：两项便宜的内容保持型切换（约束放在文件还是只在对话中；只判终态还是加过程检查）测出的增益，比静态增益或留出增益更能预测该方法在真实交互会话（SWE-Together）中的增益；并说明哪类方法机制会让静态结论在交互下翻转。方法开发者和采用者可以用一次额外的静态运行判断报告的增益是否值得信，而不必搭建用户模拟器与评判器。
- 贡献自评：重要性 7.0 / 新颖度 7.0 / 有效性 6.5（依据：2608.11242 同会话压缩前后 0/100→30/100 误删、2610.31778 SWE-chat 过程指令丢 35.9% vs 功能需求 6.2%、HDA SWE-bench 搜索增益与留出增益方向不一、CHASE Syn-Ledger 原口径与反事实口径增益排序反转；未知：切换测出的依赖是否就是交互会话中起作用的那一部分；模型层面静态与交互排序一致是反方向边界）；待预研：各方法交互增益的大小与预测相关系数。
- 可行性：pass（压缩代码 aisa-group/compaction 基于 OpenCode；SWE-Together 发布 109 个任务、模拟器提示、评判器，原生支持 opencode 与 mini-swe-agent；HDA 发布 SWE-bench 上 4 个 Qwen 执行模型的基线与演化 harness 及 SkillOpt 技能；SC 提取器在 ZhiqiEliWang/compaction-integrity。风险：SWE-Together 评判器默认在 E2B 沙箱运行，docker 模式下评判仍需 E2B；Meta-Harness 产物是独立 ReAct 脚本，接入模拟器回合需写适配层。）
- 自评分：`6.8/10`
- 一段话概括：Claim：在编码 agent 上，方法相对对照的增益在静态基准、两项结构切换、真实交互会话三种口径下不按同一比例变化；切换口径下的增益（以及按机制预先标注的依赖）预测交互增益，优于静态增益和 HDA 留出增益。方法：同一基座模型下取约 16 个方法–对照对（压缩族：5 种策略 + SC 提取器相对默认自摘要，2 个执行模型；演化族：HDA 发布的 Meta-Harness ×4 执行模型、SkillOpt ×2），先在 SWE-bench Verified 98 个任务上测静态增益与切换增益，再在 SWE-Together 109 个任务上测交互增益，比较三种预测量与交互增益的秩相关并检验事先登记的符号预测。
- Story line：静态基准上两族方法的增益在换口径后都出现不保留（2608.11242 Table 1；2610.31778 Fig. 4b；HDA SWE-bench Table 1）→ 被忽视的是：模型排名可迁移不等于方法增益可迁移，因为方法往往正是依赖基准提供的冗余（可重读的目标、只判终态）来"免费"获得增益，而现有检验（留出任务）不改变这些结构 → 本 Idea 只在静态基准上切换这两项结构、测方法的依赖，用真实会话重建的交互基准作外部目标检验预测力 → 若成立，切换增益与交互增益的秩相关显著高于静态增益与留出增益；若切换不优于静态增益（即统一打折），则结构依赖不是方法迁移的主要因素，结论可推翻。

### IDEA-004：方法增益"在线上"：结构切换下增益的统一折扣与有效保留（相似领域成熟方法迁移）

- 来源：`相似领域成熟方法迁移`
- 父 Idea：`无`
- 状态：`covered`（并入 IDEA-003 作为零假设）
- 定位关键词：accuracy on the line；effective robustness；harness evolution；context compaction
- 一句话背景：分布鲁棒性文献发现跨模型的分布内与分布外准确率常呈线性关系（Miller et al. 2021），偏离直线的部分称有效鲁棒性。
- 与起点问题的关系：子问题；把"保留率"改成"相对统一折扣线的偏离"。
- 主贡献：若方法增益在结构切换下"在线上"，基准可以给一个统一折扣系数；偏离部分对应方法特有的结构依赖。
- 贡献自评：重要性 6.0 / 新颖度 6.5 / 有效性 5.0（CHASE Syn-Ledger 原口径与反事实口径增益排序反转，是"在线上"的直接反例）
- 可行性：pass
- 自评分：`5.5/10`

### IDEA-007：在无中途用户输入的环境中做 agentic RL，是否让编码 agent 在上下文完整时也不再响应中途用户指令（邻近新问题，领域共性不足）

- 状态：`needs_revision`（第 3 轮未过，子候选 IDEA-008）
- 定位关键词：agentic reinforcement learning；SWE-bench Verified；R2E-Gym；instruction following；multi-turn interaction；interruption
- 一句话背景：开源编码 agent 的 agentic RL（DeepSWE、SkyRL 等）在 R2E-Gym/SWE-Gym 这类"目标只在首条消息、运行中没有真人输入"的环境里训练，奖励只看首轮目标是否完成；本 Idea 研究这样训练出的策略在部署中是否学会忽略中途到来的用户指令。

### IDEA-008：把注入防御中的来源分段嵌入迁移到编码 agent 轨迹：同一机制提升真人中途指令的采纳、压低工具输出中伪指令的采纳（相似领域成熟方法迁移）

- 来源：`相似领域成熟方法迁移`
- 父 Idea：`IDEA-007`
- 状态：`needs_revision`（第 4 轮未过；运行停止）
- 定位关键词：instructional segment embedding；instruction hierarchy；prompt injection；agentic coding；multi-turn instruction following；tool observations
- 一句话背景：编码 agent 的 ReAct 式 harness（R2E-Gym 非函数调用分支、mini-swe-agent 式、HDA 基线）把工具观察与真人回合都放进 user 角色，而模型按文本"听起来像谁"判断来源；本 Idea 研究来源信息缺失是否是中途真人指令采纳差、同时又易受观察中伪指令影响的共同原因。
- 与起点问题的关系：邻近新问题；保留起点结构性质"运行中没有真人输入"（训练轨迹中首轮之后的 user 内容全是环境输出）这一来源，但对象换成一个训练方法及其在交互口径下的效果；起点的跨方法族增益保留率预测未回答。
- 主贡献：若成立，得到一个可直接用于 agentic 后训练的方法：在 agent 轨迹微调中为 system / 真人 / 环境观察 / 助手四类片段加来源嵌入（ISE 或 ASIDE 式），使同一模型对真人中途指令采纳更高、对工具输出中伪装成指令的文本采纳更低；这把注入防御领域"压低低权限片段"的机制改成 agent 场景下的双向目标。
- 贡献自评：重要性 7.0 / 新颖度 7.5 / 有效性 5.5（依据：ISE 2410.09102、ASIDE 2503.10566 在注入防御上有效；2603.12277 显示模型按文风而非角色标签判断来源，说明只靠角色标签不够；R2E-Gym agent.py 第 491/497 行观察以 user 角色追加。未知与反方向：MTAC-IFBench §4.4 Fig. 6 显示即使在角色分明的 Claude Code/OpenCode 下，用户指令中的约束随轮次衰减也明显快于仓库策略文件中的约束——衰减的主因可能是信息不持久而非来源不清，这会限制来源嵌入的作用；待预研：来源模糊在中途指令失败中占多大比例）。
- 可行性：pass（微调 Qwen3-8B；轨迹数据可从公开 SWE-smith/SWE-rebench 轨迹构造；ASIDE 代码公开）
- 自评分：`6.3/10`
- 一段话概括：Claim：在同样的增广数据下（含中途真人约束的轨迹 + 观察中含伪指令的轨迹），加来源嵌入的微调比只用角色标签的微调，在"真人中途指令采纳率 − 观察中伪指令采纳率"上更高，且优势集中在伪指令文风与真人消息相近的样本上（来源模糊预测）。先做零训练诊断：对基座模型，把同一条中途指令分别作为 user 消息、附在观察里、以系统角色投递，测采纳差异；若三者相同且与仓库文件中的约束同样衰减，说明来源不是瓶颈，停止。
- Story line：ReAct 式 harness 与训练环境让 user 角色同时承载真人指令与环境输出（R2E-Gym）→ 模型按文风判断来源（2603.12277），于是同时出现"真人中途指令不被采纳"（MTAC-IFBench、SWE-Interact）与"观察里的伪指令被执行"（提示注入）→ 注入防御的来源嵌入只做了单向压低，本 Idea 把它改成双向目标并放进 agent 轨迹微调 → 预期来源嵌入在双向指标上优于同数据的角色标签基线；若不优于，说明增益来自数据而非来源表示，主张被推翻。
- 打分理由：新颖度有迁移依据，但有效性的关键前提（来源模糊是主因）与 MTAC-IFBench 的"持久性"证据存在张力；方法族在注入防御已成熟，目标领域的增益大小未知。
- Idea 生成依据：2410.09102；2503.10566；2603.12277；2512.03720；R2E-Gym agent.py；MTAC-IFBench 2609.14992 §4.3–4.4；Laguna 2605.27605 §4.3.2（IF 数据增强）。
- 自评分轻量新意依据：检索"instructional segment embedding agents tool outputs helpfulness""provenance-aware training coding agent user turns tool observations"未检出把来源嵌入用于提升 agent 中途真人指令采纳的工作；ISE、ASIDE、CAHL 只用于安全/注入。需要 reviewer 检索。
- 与输入论文的关系：不适用
- 本 Idea 的独立创新点：来源嵌入在 agent 轨迹中的双向目标（提升真人、压低环境中的伪指令）。
