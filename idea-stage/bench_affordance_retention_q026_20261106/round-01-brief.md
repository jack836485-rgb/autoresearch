## 背景

**定位关键词：** context compaction；harness evolution；SWE-bench Verified；user simulator；side constraints

**一句话定位：** 编码 agent 的方法研究（上下文压缩、harness 与技能演化）用静态基准选方法，本 Idea 研究这类方法相对其对照的增益能否迁移到真实交互会话、以及能否事先预测哪些增益会掉。

**与起点问题的关系：** 子问题。保留"方法增益换到交互／过程口径后还剩多少、能否事先预测"这一对象；把"按结构性质给多个基准打分"改成"在同一静态基准上切换两项结构条件、测各方法的依赖"，并用真实会话重建的交互基准检验预测力。原问题中跨多个基准的结构评分、非编码领域、留出任务族口径（HDA 已部分回答）不在本 Idea 内。

## 核心 Claim

成功后新增的东西：一个方法层面的迁移预测结论和一套便宜的检验。在编码 agent 上，方法相对对照的增益从静态基准换到真实交互会话时，不是所有方法按同一比例打折；只在静态基准上做两项内容保持型切换（同样的约束放在仓库文件里 vs 只在运行中以用户消息给出；只判测试通过 vs 再加确定性过程检查）测得的增益，比静态增益或留出增益更能预测该方法在交互会话中的增益。方法开发者因此可以用一次额外的静态运行判断报告的增益在交互使用中是否可信，并知道哪类机制会让静态结论翻转。

可推翻的判断：在约 12–15 个"方法–对照"对上，切换口径增益与交互增益的秩相关显著高于静态增益（以及演化族的 HDA 留出增益）与交互增益的秩相关；若二者相当（即各方法统一打折），则结构依赖不是方法增益迁移的主要因素，主张不成立。

目前支持预期的依据：(1) 压缩族：2608.11242 Table 1 中同一会话、同一邮箱状态下，压缩前 0/100 会话越权删除，压缩后 30/100，其中 28 个摘要丢了该约束；2610.31778 App. 6.11 在 SWE-chat 真实会话上，功能需求丢 6.2%，过程指令丢 35.9%、范围排除丢 36.8%，而在 PaperBench/ProgramBench 上没有一种压缩策略在置信区间外优于默认自摘要（Fig. 3）——说明静态基准上的"策略无差别"可能来自信息可重读。(2) 演化族：HDA（2610.22466）SWE-bench 发布结果中，Meta-Harness 对 Qwen3-Coder-30B-A3B 搜索集 56.2→68.8、测试集 40.0→34.0，对 Qwen3-30B-A3B 25.0→58.3、12.0→26.0，同一框架下静态增益的迁移方向不一；CHASE（2609.18366）Table 2 中原口径增益最高的方法（+11.70）在保持语义的协议变换下只剩 +3.04，另一方法从 +5.29 变为 +23.08，排序反转。适用条件：这些证据来自压缩与 harness 演化两族各自的设定，且多为前沿模型或不同任务。未知：静态基准上的两项切换捕捉到的依赖，是否就是交互会话中起作用的那部分；反方向边界是模型层面静态与交互排序大体一致（SWE-Together 2606.29957：更强 agent 交互成功率更高、所需纠正更少），所以本主张只针对方法增益，不针对模型排名。增益与相关系数的大小待预研。

## 方法设计的核心思想

输入：同一基座模型下的方法–对照对。压缩族在 OpenCode 中实现（相对默认自摘要）：旧工具输出裁剪、丢弃推理块、小模型摘要、落盘无损副本、约束单独保存再拼回（SC 提取器），强制低阈值触发压缩；演化族用 HDA 发布的 Meta-Harness 与 SkillOpt 产物（相对各自基线 harness）。

动作：(a) 静态口径：SWE-bench Verified 原任务，只判测试通过；(b) 切换口径：给每个任务加 3 条带确定性检查器的过程／范围约束（不改测试文件、不改指定目录外的文件、不新增依赖、不改公开函数签名），内容相同，一种放在任务引用的仓库规则文件里，一种只在第 k 步以用户消息给出；判分为"测试通过且无违规"；(c) 交互口径：SWE-Together 真实会话重建任务，按其原定义判正确性与 User Correction。事先按机制为每个方法登记其增益是否依赖"信息可重读"或"只判终态"及预测符号。

输出：每对方法的三种增益；三种预测量（静态增益、切换增益、留出增益）与交互增益的秩相关及差异的置信区间；登记的符号预测命中率；与"统一打折"零假设（交互增益 = 常数 × 静态增益）的残差比较。

与最高近邻的关键差别：CHASE 与 HDA 只在 harness 演化一个方法族内检验增益是否经得起协议变换或留出，变换不涉及信息是否只在对话里、是否只判终态，也不以真实交互会话为目标；SWE-Together、InterruptBench 等交互基准比较的是模型而非方法增益；2608.11242、2610.31778 测压缩丢约束，不检验能否预测方法在交互会话中的增益。

## 最小实验

模型与数据：执行模型 Qwen3.6-27B 与 Qwen3-Coder-30B-A3B-Instruct（HDA 已发布这两个模型的 Meta-Harness 产物，Qwen3.6-27B 另有 SkillOpt 产物；HDA 测试集分别为 66.0 与 40.0，避免交互基准上的地板效应）；视预研再加 Qwen3-30B-A3B-Instruct。静态与切换口径用 HDA 的 SWE-bench Verified 98 题（48 搜索 + 50 测试），交互口径用 SWE-Together 109 题。

方法–对照对：压缩族 2 个执行模型 × {裁剪、小模型摘要（Qwen3-4B 代替原文的 Haiku）、落盘、SC 提取器}，Qwen3.6-27B 另加丢弃推理块，共 9 对；演化族 Meta-Harness × 2–3 个执行模型、SkillOpt × 1，共 3–4 对。

强对照与相同核心条件：每对内同一执行模型、同一任务、同一步数与 token 上限、同一压缩阈值；预测量对照为静态增益、HDA 留出增益（演化族直接用其 50 题测试集；压缩族无留出概念，用 48/50 两半间增益一致性代替并注明）、统一打折零假设。CHASE 的变换作为预测量不复现：其变换由 Challenger 针对单个 harness 搜索，不能跨族对齐，所以本 Idea 不声称优于 CHASE。

复现路线：压缩策略用 aisa-group/compaction（已核验：OpenCode 副本，README 给出 compaction.* 配置键，构建本地二进制后 agent 端可接 vLLM）；SC 提取器用论文给出的 ZhiqiEliWang/compaction-integrity，接到压缩后上下文拼接处；Meta-Harness 与 SkillOpt 用 HDA 仓库 artifacts/metaharness_swebench、skillopt_swebench 下已发布的 baseline/evolved 文件与其 ReAct 运行器；SWE-Together 已核验发布 109 个任务（每个含 Dockerfile、tests/ 门控套件、模拟器提示、参考补丁与冻结的评判细则），原生支持 opencode 与 mini-swe-agent，HDA 的 ReAct 运行器需写适配层，在 agent 提交时咨询模拟器、有消息则继续。

关键数据：注入约束和检查器需新建（每任务 3 条，检查基于最终 diff 与命令日志，约 1–2 人日）；未知是约束是否真与解题冲突——先用基线 agent 在 20 题上测违规率，违规率接近 0 则换约束。SWE-Together 的评判器只能用 Claude 模型、模拟器默认 Sonnet 5.5，全量调用超出预算，所以交互口径的正确性用每题自带的 tests/ 门控套件，模拟器改接自托管的 Qwen3.6-35B-A3B（需放开代码里"vLLM 只用于 agent 席位"的限制），用其 Intent Coverage 指标核对模拟器保真度；Claude 评判器（Haiku 4.5）只在约 20% 运行上做与 tests 门控的一致性校准。

结果判据：切换增益与交互增益的秩相关减去静态增益与交互增益的秩相关，按任务自助法给 95% 区间；区间在 0 以上支持主张，包含 0 或为负则推翻。

成本：静态+切换约 6,000 次运行、交互约 1,300 次运行（每对 1 次重复，关键对 2 次），在 8×A100 上用 vLLM 并发约 3–4 天；模拟器自托管不计 API；评判器校准约 300 次 Haiku 运行，估计 500–700 元；E2B 沙箱费用约数十元。预研只先跑每个执行模型的基线在 SWE-Together 上的通过率（判断是否地板）和 20 题约束违规率，约 1 天、2×A100。
