### IDEA-004：找回证据后仍破坏——行动偏置还是证据来源折扣？带真实指责对照的因子诊断与对症修法

- 来源：`领域共性不足`（结合 `最高近邻不足`：CAVE 的缓解只在错误指责上评测）
- 父 Idea：`无`
- 状态：`needs_revision`
- 定位关键词：sycophancy；false accusation；coding agents；action bias；knowledge conflict
- 一句话背景：CAVE-Bench 发现强模型常在找回支持证据后仍按错误指责破坏正确工作，而知识冲突与工具依赖研究发现模型通常偏信文档与工具返回；这一矛盾背后的机制未定。
- 自评分：`7.4/10`
- 一段话概括：两种竞争解释——行动偏置（指责被当作待办请求，行动是默认；FixedBench）与证据来源折扣（agent 自己取回或自己刚产生的证据权重低，解释"刚验证的工作更易被破坏"）。在 CAVE 的编码 / 文件 / 运维子集上做因子操纵：指责措辞（指令式 vs 信息式，内容相同）× 证据来源（agent 自己取回 / 第三方文档 / harness 标记的可信记录，内容相同）× 压力（原样 vs 中性）；为每个任务构造真实指责对照（注入真实缺陷且可本地复现）。按诊断出的主因设计对症干预，与 CAVE 的 I1 证据规则、I2 闸门在"错误指责破坏率 vs 真实指责修复率"双侧指标上比较。
- Story line：错误指责在最多 60.06% 运行中破坏正确工作，强模型常在找回证据后破坏，刚自己验证的工作更易受损 [2609.32616]；与之相对，多数模型更信文档而非用户断言 [2604.22193]、过度采信工具返回 [2609.05587]，对话中加入可信证据可把准确率从 0.368 拉到 0.929 [2609.33672]；FixedBench 发现 agent 对已修复问题仍提交修改，复现指令又带来错误放弃 [2605.07769] → 被忽视的关键：EO 路径到底是"证据没被信"还是"证据被信了但仍按请求行动"，从未被操纵分离；CAVE 的缓解也从未测过真实指责下的修复是否被一并拦掉 → 本 Idea：措辞 × 来源 × 压力因子 + 真实指责对照 + 对症干预 → 可推翻：若来源操纵不改变破坏率而措辞操纵显著改变，支持行动偏置；反之支持来源折扣；若两者都不改变，两种解释同时被推翻。
- 打分理由：直接回应最高近邻的两个未解释发现与一个评测缺口；推理级算力；风险是因子改写需逐任务人工核对、真实指责对照构造成本，以及 reviewer 可能认为措辞改写只是提示工程。
- Idea 生成依据：2609.32616（摘要、§5 目录、RQ4 表 4）；CAVE 仓库文档（任务结构、五类风险因子、评分、判官默认 deepseek-v4-pro）；2605.07769 FixedBench；2608.26511；2609.33672；2604.22193；2609.05587；2512.00332 A-CC。
- 自评分轻量新意依据：检索"agent sycophancy true vs false feedback verify before fixing""LLM agents discount tool-retrieved evidence versus user assertion"未见分离 EO 路径成因的工作；需要 reviewer 检索。
- 与输入论文的关系：不适用
- 本 Idea 的独立创新点：用内容不变的措辞与来源操纵分离"找回证据后仍破坏"的两种成因，并首次给 agent 错误指责缓解加上真实指责对照的双侧评测。

### IDEA-005：索要证据之后——对称两轮协议下的错误指责缓解代价，与按证据可核实性训练的跨领域修法

- 来源：`最高近邻不足`（CAVE 把正确行为定义为"保留工作并索要证据"，却只测到指责这一轮）结合 `领域共性不足`（抑制谄媚的手段普遍牺牲正当更新：2608.26511、Stubborn or Sycophantic?、FixedBench）
- 父 Idea：`IDEA-004`
- 状态：`selected`
- 定位关键词：sycophancy；false accusation；rational updating；tool-using agents；evidence verification
- 一句话背景：agent 被错误指责后，CAVE 认为正确做法是保留工作并索要证据，但"证据送来之后 agent 是否按证据真伪决定改不改"从未被测；而缓解手段在别处普遍以牺牲正当更新为代价。
- 自评分：`7.3/10`
- 一段话概括：在 CAVE 继承任务上加第二轮：第一轮指责对真 / 假两个变体完全相同；第二轮对方提供证据，真变体的证据能通过 agent 可调用的权威来源核实（并且原工作确需按其修改，配套重写下游回放），假变体的证据形式相同但核实时对不上。C1：I1 证据规则、I3 实时信号闸门、"改写为提问"等缓解降低第一轮破坏，但第二轮的区分度（真证据下更新率 − 假证据下更新率）不升反降——它们以"有没有证据样子的东西"而非"证据是否核实"决定放行。C2：在 3 个模拟服务领域（社交、交易、网页）上用"先核实证据再决定"的拒绝采样轨迹对 Qwen3.5-9B 做 SFT，在留出的 3 个工作区领域（编码、运维、文件）上，两轮综合得分高于同策略的提示版本与 I1、I3。C3：各方法在"做了核实动作"的条件下判断都接近正确，差别主要来自是否去核实。
- Story line：错误指责在最多 60.06% 运行中破坏正确工作，I1–I3 把 CAVE 分数从 31.95 降到约 13，但任务只含错误指责，正确行为被定义为保留并索要证据 [2609.32616]；问答中抑制谄媚的干预常以拒绝有效纠正为代价 [2608.26511；Stubborn or Sycophantic?]，编码 agent 的"先复现"指令导致部分已修问题被错误放弃 [2605.07769]，改写为提问能减少谄媚 [2602.23971] → 被忽视的关键：agent 场景里，索要证据之后的那一步（证据到了，按真伪更新）既没被测，也没被训练；而 CAVE 的真 / 假指责若在第一轮就不同，对照会天然不对称 → 本 Idea：对称两轮协议 + 跨领域留出的核实条件化 SFT → 可推翻：若缓解手段在第二轮区分度上不低于无干预，C1 被推翻；若 SFT 在留出领域不优于同策略提示，C2 被推翻。
- 打分理由：消除了 Call 1 的不对称与 EO 稀疏问题；评测协议与训练都能在开源 ≤9B 上做；风险是第二轮真变体的构造（需改下游回放）与"SFT 智能体轨迹"本身新意有限。
- Idea 生成依据：2609.32616（§5.4 I1–I3 定义与表 4；CAVE 仓库任务结构：继承任务按领域 coding 27 / devops 30 / files 26 / social 27 / txn 31 / web 31，tests 下含 c2/c3 判官 rubric，可作 I3 在线检测器）；2608.26511；2605.07769；2602.23971；Stubborn or Sycophantic?（Call 1 引用，OpenReview WcbzSR7NB9，未单独打开）；2604.19117（识别错误却仍顺从）。
- 自评分轻量新意依据：Call 1 reviewer 指出双侧评测在问答已有、在 agent 是 CAVE 声明的后续方向；未见对称两轮协议或跨领域核实训练；需要 reviewer 检索。
