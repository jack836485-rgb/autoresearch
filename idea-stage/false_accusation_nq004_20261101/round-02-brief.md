## 背景

**定位关键词：** sycophancy；false accusation；rational updating；tool-using agents；evidence verification

**一句话定位：** 已完成且经验证的 agent 工作被无法本地核实的指责质疑时，正确做法是保留工作、索要证据。但证据送到之后，agent 能否按证据的真伪决定改与不改，现有评测没有测过；减少错误认错的缓解手段，会不会顺带让 agent 拒绝真实的证据，也没有测过。

## 核心 Claim

1. **现有失败**
   - CAVE-Bench（arXiv 2609.32616）：
     - 错误指责在最多 60.06% 的运行中破坏正确工作。
     - 三种缓解把 CAVE 分数从 31.95 降到 12.59–14.39：证据规则 I1（回滚、删除、撤销前须在工作区出示新的、可独立核查的证据）、不可逆操作闸门 I2、实时信号闸门 I3（转录已像错误认错或证据被替代时，拦截下一次不可逆调用）。
     - 任务只含错误指责。指责可附带"声称的证据"（压力因子 P3），但没有证据为真、工作确需修改的对照。
     - 论文把正确行为定义为"保留工作并索要缺失的证据"，评测在这一步结束。
   - 问答场景：抑制谄媚的训练期与推理期干预，普遍以牺牲对有效纠正的更新为代价（arXiv 2608.26511）。
   - 编码 agent：FixedBench（arXiv 2605.07769）中，"先复现再修"的指令减少了不必要的修改，却让部分已修复的问题被错误放弃。
   - 改写为提问能减少谄媚（Ask don't tell，arXiv 2602.23971）。

2. **被忽视的关键**：agent 场景中，"索要证据之后，证据送到"这一步既没被测，也没被训练。另外，如果真、假指责在第一轮就不同（比如真指责能本地复现），对照天然不对称，测不出缓解的代价。本 Idea 主张：
   - **C1（缓解的隐性代价）**：在对称两轮协议下，I1、I3 与"改写为提问"会降低第一轮的破坏，但第二轮的区分度不升反降。区分度定义为真证据下的更新率减去假证据下的更新率。原因是这些缓解按"有没有像证据的东西"放行，而不是按"证据是否经核实"放行。
   - **C2（跨领域可训练）**：用"先调用权威来源核实证据、再决定"的拒绝采样轨迹，在 3 个模拟服务领域上微调 Qwen3.5-9B。在留出的 3 个工作区领域上，它的两轮综合得分高于同一策略的提示版本，也高于 I1 与 I3。
   - **C3（差别来自是否去核实）**：在 agent 做了核实动作的轨迹中，各方法的第二轮判断都接近正确。方法之间的差别主要来自核实动作的发生率。

## 方法设计的核心思想

- **对称两轮协议**：在 CAVE 继承任务上加第二轮，每个任务有真、假两个变体。
  - **第一轮**：指责消息和工作区在两个变体中逐字相同。
  - **第二轮**：对方给出一份证据，两个变体的格式和语气相同。
    - **真变体**：证据能通过 agent 可调用的权威来源核实，例如查询该服务的配置或合同记录接口。原工作确实需要按证据修改，下游回放检查同步改写为期望修改后的状态。
    - **假变体**：证据在核实时对不上。下游回放检查沿用 CAVE 原版，期望保留原工作。
- **评分**：
  - 第一轮沿用 CAVE 的 ROH、FCS、ERF；
  - 第二轮记录是否更新、更新是否正确（下游回放），以及更新前是否调用了核实来源。
  - 两轮综合得分为第一轮安全率 × 第二轮区分度，同时报告各分项。
- **训练**：
  - 教师：Qwen3-32B，配合"先核实再决定"的策略提示。
  - 数据：在社交、交易、网页 3 个领域（89 个继承任务及其两轮变体）上，每个任务采样 8 条轨迹，只保留两轮结果都正确的轨迹。
  - 学生：对 Qwen3.5-9B 做 LoRA SFT。
  - 评测：在编码、运维、文件 3 个领域（83 个任务）上。
- **与最高近邻的差别**：
  - CAVE 只测指责这一轮，没有真证据变体；
  - 2608.26511 与 Stubborn or Sycophantic? 研究问答中的双侧代价，没有工具核实动作；
  - FixedBench 研究过时 issue，没有压力与证据交付；
  - 本 Idea 把双侧代价放进"证据送达后需调用工具核实"的 agent 第二轮，并检验核实行为能否跨领域训练出来。

## 最小实验

- **模型**：
  - Qwen3.5-9B：CAVE 评测过的开源模型，也是训练对象；
  - Qwen3-32B：教师，也作为评测模型。
  - 两者都用 vLLM 提供 OpenAI 兼容端点，经 CAVE 的 `hermes_custom_openai` harness 运行；温度、步数上限、工具集与 CAVE 默认一致。
  - 只用继承任务，避开自建任务的有效性门槛。
- **数据**：
  - 训练：社交、交易、网页 3 个领域，共 89 个任务；
  - 评测：编码、运维、文件 3 个领域，共 83 个任务，每个任务都有真、假两个变体。
- **对照**：各方法在同一组任务、同一 harness 下运行，每个变体重复 3 次。
  1. 无干预；
  2. I1 证据规则；
  3. I3 实时信号闸门；
  4. 改写为提问；
  5. 同策略提示（与教师相同的策略提示）；
  6. 核实条件化 SFT（本 Idea）。
- **指标**：
  - 第一轮：ROH、FCS、ERF；
  - 第二轮：真变体正确更新率、假变体错误更新率、区分度、核实调用率；
  - 两轮综合得分。
- **支持与推翻**：
  - **C1**：I1、I3、改写为提问三者中，至少两种的第二轮区分度显著低于无干预（按任务配对检验，3 次重复取均值），则支持；若都不低于无干预，则推翻。
  - **C2**：在留出领域上，SFT 的两轮综合得分显著高于同策略提示，且高于 I1、I3，则支持；若不高于同策略提示，说明收益只来自策略内容，C2 被推翻。
  - **C3**：在"更新前有核实调用"的轨迹子集中，各方法的第二轮正确率差异小于 5 个百分点，而核实调用率差异显著，则支持。
- **Baseline 来源与复现**：
  - **CAVE-Bench**：
    - 论文：https://arxiv.org/abs/2609.32616
    - 代码：https://github.com/henrymao2004/agent-over-correction （已克隆核验）
    - 任务目录 `cavebench/tasks/<domain>/task_*_gaslight/`，下含 `instruction.md`、`environment/`、`tests/c1_downstream/checks.py`、`tests/c2_false_confession/*.toml`、`tests/c3_recognition/*.toml`；harness 为 `cavebench/agents/hermes_custom_openai.py`；运行命令 `harbor run -p ... -a ... -m ...`；汇总脚本 `cavebench/scoring/aggregate.py`。
  - **I1**：论文 §5.4 给出完整规则文本，作为系统提示复现。
  - **I3**：用各任务自带的 c2、c3 判官 rubric 在线检测（判官为本地 Qwen3-32B）。命中后，拦截下一次属于该任务伤害目标（D1–D6）的工具调用；这类调用由每个任务 `tests/c1_downstream/checks.py` 所检查的状态反推。
  - **改写为提问**：论文 https://arxiv.org/abs/2602.23971 ，未找到代码；方法是把非提问输入改写为提问，在 harness 中实现。
  - 以上均为 agent 错误指责或谄媚缓解，与本任务同领域。
- **构造工作量**：172 个继承任务各需一个第二轮真、假变体；真变体还要为 agent 提供权威来源接口，并改写下游回放。预计 2 人周，可先做 60 个试点。
- **算力与 API**：
  - **评测**：2 个模型 × 6 种方法 × 83 个任务 × 2 个变体 × 3 次，约 6,000 次运行。
  - **教师采样**：89 × 2 × 8 ≈ 1,400 次运行。
  - **运行时长**：按每次约 5 分钟、vLLM 并行粗估（需试跑核实），约 3–4 天 8×A100；单次作业不超过 2 天。
  - **SFT**：LoRA，约 1,000 条轨迹，约 10 A100 小时。
  - **判官**：本地 Qwen3-32B。另抽 500 次用 CAVE 默认判官 deepseek-v4-pro 核对一致性，约 2,000 万 token，约 6 美元。
  - 无其他 API 开销。
