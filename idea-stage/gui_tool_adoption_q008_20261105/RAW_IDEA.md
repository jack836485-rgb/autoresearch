## 具体问题
同一混合 GUI–MCP harness 中，工具可用对推理模型有益、对非推理模型有害，且即使受益模型也只在约四分之一可达工具的任务上调用工具；用稠密奖励把采用率提高一个数量级后，留出准确率并不跟着提高——工具“采用”与工具“胜任”在哪里脱节，什么决定某一步该走 GUI 还是工具？

## 关键证据
| 作品 | 原文链接 | 具体观察 | 证据边界 |
|---|---|---|---|
| Screenshots or Tools? Eliciting Tool Use and Managing Multimodal Context in Hybrid GUI–MCP Computer-Use Agents（Peking University、UESTC、Renmin University、Xiaohongshu） | https://arxiv.org/abs/2608.03327 | MCP 使推理模型 +4.0pp、非推理模型 −5.9pp（均超 2 SE）；推理模型只在 55/309 题调用工具，为可达题（230 题）的 23.9%，非推理模型 13.9%；VLC 17 题中 16 题可达但从未调用；稠密奖励使采用率提高一个数量级并保持到贪心解码，但留出准确率不随之提高，作者结论为“RL 触及了工具决策而非工具胜任” | 单一基准；作者归因“训练从未要求走更便宜的路线”为解释，未做训练数据干预 |

打磨阶段补读（同一论文）：工具被调用的任务成功率更低（writer 上调用 42% 对未调用 82%），作者归因为难度自选择（模型在更难的任务上调用工具）与复杂工具参数化错误，calc 与 impress 上几乎无差异；推理/非推理模型的错误终止率分别为 21.7%（67/309）与 33.0%（102/309），非推理模型在 2 个任务中出现 97 次幻觉工具名；稠密奖励作用于 24 个任务子集，电子表格采用率 23 步内从 0.03 升至 0.33（贪心 0.02→0.29），步级使用 ×4.7；训练用 1 节点 8×A100 80GB、Qwen3-VL-8B-Thinking、96 个并行 Docker VM。

## 已有解决方法与剩余边界
- 已有解决方法：稠密采用奖励（只改采用率，不改准确率）；ToolCUA（NeurIPS 2026，GUI–工具路径编排）与 UltraCUA（arXiv:2510.17790，混合动作基础模型）在训练侧引入工具调用；本轮未读其正文
- 已支持的解释：工具效果的符号随工具决策行为变化（非推理模型忽略、错名或在工具附近错误终止）
- 尚未解决：采用率提高后准确率不变的原因（选错工具时机、参数化错误、还是调用后上下文管理）未分离；逐步“该走 GUI 还是工具”的判据未知；ToolCUA 等是否已解决胜任问题需下游查新。

## 待验证解释与分歧
- 待验证解释：“已有更便宜路线却从未被训练去走”（作者解释）
- 跨论文分歧：ToolCUA（arXiv:2605.12481）以交错 GUI–工具轨迹 SFT + 切换点单轮 RL + Tool-Efficient Path Reward 在线 RL，在 OSWorld-MCP 上报告 46.85% 且比纯 GUI 高 3.9 点；2608.03327 的稠密采用奖励提高采用却不提高留出准确率。两者的数据、奖励与起点不同，尚未对齐。

## 可检验切口与查新状态
- 可检验切口：在采用率被稠密奖励拉高的检查点上，按“调用是否必要/参数是否正确/调用后是否误用截图”分解失败；比较同任务走 GUI 与走工具的成功率以给出逐步判据。
- 查新状态：本轮反证检索：ToolCUA（NeurIPS 2026）研究 GUI–工具路径编排、UltraCUA 训练混合动作；“采用≠胜任”的分解未检出直接研究；打磨阶段补检：Hybrid Computer Use（Microsoft Research 等，2026-10）用技能与动作守卫把畸形参数调用从 17.4% 降到 1.4%。

## 问题锚点（Problem Anchor）
- **起点问题**：同时能用 GUI 原子动作与 MCP/工具调用的计算机使用智能体，在工具可达时很少调用工具；工具可用对推理模型有益、对非推理模型有害；用奖励把采用率拉高后准确率不变。需要回答工具"采用"与"胜任"在哪里脱节、什么决定某任务/某步该走 GUI 还是工具，以及能否据此让采用真正转化为准确率。
- **初始任务与评测**：OSWorld-MCP（309 题，230 题工具可达）；任务准确率、采用率、错误终止率。
- **瓶颈与证据边界**：单一基准、两类模型；作者解释"训练从未要求走更便宜的路线"未经数据干预；ToolCUA 与 2608.03327 结论方向不同且条件未对齐。
- **用户资源约束**：正式实验 8×A100 80GB，单次最好不超过 5 天；预研 2×A100 80GB / 4×L40 48GB / 8×4090 24GB；付费 API 1000 元以内可自主决定；token 资源稀缺。OSWorld/OSWorld-MCP 的 Docker VM 需要 KVM，服务器是否支持尚未确认。
- **时间与目标**：自 2026-10 起半年内投出一篇主会论文。
- **非目标**：不做世界模型、视频生成、机器人方向。
- **进入实验规划的成功条件**：独立 Reviewer 两次（常规 + 复核）判定三项贡献分都 ≥6 且至少两项 ≥8、可行性 pass、`experiment_ready`、无致命阻断；最小实验能在上述算力内完成，强基线有可信复现路线。
