## 术语与缩写表

| 术语 | 全称或中文 | 本方案中的含义 |
|---|---|---|
| ScrambleToolBench | 匿名工具发现基准 | 工具名称被打乱，agent必须通过公开调用结果发现其行为，后续任务可能重新分配名称。 |
| alias | 工具别名 | 当前可以调用的名字；名字改变不一定意味着功能改变。 |
| partial map | 不完整工具地图 | 已经发现一部分别名对应的行为，其余关系仍未知。 |
| mapping drift | 映射变化 | 一组工具的别名重新分配，旧的名字—行为对应不再成立。 |
| cycle tracing | 沿旧表追踪循环 | 某别名返回了别的已知行为时，接着调用该行为旧别名来寻找目标；这是原论文已有策略。 |
| perfect matching | 完美匹配 | 为每个别名分配一个不同的行为角色，满足工具一一对应结构。 |
| 最少改动解释集合 | 本方案的操作性定义 | 所有满足当前观察、且改变已有旧绑定数量最少的匹配；它是候选解释，不是已验证真相。 |
| probe | 诊断调用 | 为区分仍可能的工具位置而调用一个别名；算入正常执行预算。 |

## Title

# 不完整工具地图中的局部漂移恢复：保留最少改动解释，只探测任务所需位置

**候选 ID：** IDEA-038。**独立审阅：** Call 21，8.4/10，`experiment_ready`，fatal blockers为空。尚未运行实验。

**定位关键词：** tool discovery；mapping drift；behavioral reasoning。

**一句话背景：** 行为发现agent需要在旧工具地图不完整、名称发生变化后，用有限调用重新定位当前任务需要的能力。

**输入角色：** 用户未指定论文；[ScrambleToolBench](https://arxiv.org/abs/2608.02358)是公开失败证据、任务来源和同任务基线，不是等待补完的论文。

**独立创新点：** 对局部变化保留所有与当前观察相容的最少改动解释，按当前目标位置而非完整地图的不确定性选择调用，避免任取一个解释就当作唯一地图。

## 1. 引言式概述

### 1.1 任务锚点与最小范围

先研究一个窄场景：公开工具集合一一对应、工具行为可以从曾见过的返回中辨认、变化主要是名称重分配。目标不是恢复全部工具，更不是构造通用API迁移框架，而是找到下一步真正需要的工具，并完成原任务。

采用ScrambleToolBench的CPU模拟器。主实验不加视觉、不训练模型、不部署真实网络工具；使用一个API actor以及CPU上的小规模匹配计算。本地GPU需求可为零，API输入输出仍计费。

### 1.2 现有方法怎样处理

原论文报告agent在工具映射变化后沿用旧信念，或者重新尝试大量工具。它给出了便宜的cycle tracing策略，但其精确恢复保证需要完整、当前的旧表；如果旧关系缺失，沿链就可能失去下一步。

只把知识存进表格还不够。一个表格通常给每种行为一个名字，容易隐藏“这里其实还有多个可能位置”。把旧表全部清空又丢掉了局部变化之外的可用知识。

最小费用匹配和主动诊断都是成熟方法。这里迁移的是“用最少必要改变解释新观察，并通过测试区分多个解释”的思想，不声称匹配算法或广义二分查询是本研究发明的。OpaqueToolsBench的工具文档学习和MCPEvol-Bench的接口演化提供相邻问题，但不能直接当成本任务的实验baseline。

### 1.3 具体瓶颈与证据边界

**已报告事实：** 原论文展示漂移后的重复旧调用、穷举与高恢复成本，并说明完整图的恢复保证在实际初期发现中未必满足。

**待验证假设：** 对不完整旧图，某一个最优匹配可能只是许多等价解释之一；把它立即当成唯一地图，会造成错误目标调用。这个假设尚无本方案实验支持。能求出一个低代价解，不等于已经知道目标位置。

例子仅用于解释：旧表知道行为A在x、B在y，其他位置未知；新观察表明x执行了B。可能是A移到了y，也可能A移到了原先未知的位置、而y出现另一个行为。如果多种解释的已知绑定改动数相同，就不应把第一个求解器返回的方案当作事实。

### 1.4 我们实际做什么

我们构建一个小型候选匹配表。当前明确观察必须满足；旧关系只是“尽可能少改”的偏好。CPU求出所有最少改动解对当前目标位置的支持，只有位置唯一时直接使用；否则选择一个最能缩小目标候选集合的合法探针。

每次新结果都重新计算。若新观察反驳了先前全部低代价解释，允许更大的改动数，不坚持旧解。算法不需要知道实际发生变化的工具集合，也不接收隐藏映射或任务答案。

### 1.5 最小实验概览

在同一个ScrambleToolBench、actor、任务流、初始可见历史和完整预算下，比较默认agent、简单知识表、cycle tracing、单最佳匹配、没有旧先验的匹配集合和本方法。自然任务结果与预先固定的部分地图诊断分别报告。只有相对单最佳匹配和cycle tracing的改善，才能支持“集合保留”的独立贡献。

### 1.6 拟验证贡献

1. 在不完整行为地图中，把“当前观察”和“旧关系偏好”分开，保留最少改动解释的目标位置集合。
2. 将恢复调用用于区分当前所需位置，避免为了当前一个动作重新发现整张图。
3. 用同预算机制消融验证集合保留是否减少过早确定，而不是只验证把知识放进JSON有用。

这些仍是拟验证贡献，不是已取得的任务收益。

## 2. 详细方法计划

### 2.1 方法直觉

先问“目标还可能在哪些名字下”，再决定是否需要试一次。

1. 原actor从公开轨迹给已辨认的工具行为临时标签，并指出下一步所需行为；标签不能来自环境真实函数名。
2. 保存已观察过的别名、参数结构、行为标签和原返回来源；未识别部分用匿名占位角色表示。
3. 任务边界后，旧绑定变成偏好；当前成功且能明确辨认行为的返回变成硬约束。超时只表明没看到结果，不删除能力。
4. CPU求最少改动匹配，并计算目标行为在所有最优匹配里可能出现的位置。
5. 唯一时调用该位置；多个时选择诊断调用。原actor仍负责合法参数、理解结果和解决任务。

### 2.2 输入、输出与成立条件

- 输入：公开别名集合、已见行为标签、旧部分绑定、当前可辨认观察、actor需要的目标标签、剩余调用预算。
- 输出：目标候选别名集合，以及一个可直接执行或需要探测的别名建议。
- 成立条件：接口映射是一一对应；已识别行为的返回足以支持区分；变化在一个任务内稳定；局部变化偏好对当前环境有用。

原始返回字段的直接匹配属于利用公开观察，不能生成哈希或新指纹后声称获得额外身份信息。行为无法辨认时保持未知；匿名占位的置换不能制造虚假的确定标签。若实际接口新增、删除或多个接口实现同一行为，就超出首版的一一对应假设，必须如实作为边界。

### 2.3 算法与数据流

先给每个候选别名—行为配对一个代价：保持旧的已知绑定为0，改变已有已知绑定为1，旧未知配对不额外惩罚。当前硬观察限制允许的边。它表达的是解释需要多大改动，不是概率校准。

令 $A$ 是公开别名集合，$F$ 是已识别行为与匿名占位角色集合，$\pi:A\to F$ 是一一匹配。$H$ 是当前硬观察集合，$c_{a,f}$ 是上述配对代价。定义：

$$
C^*=\min_{\pi\text{ 满足 }H}\sum_{a\in A}c_{a,\pi(a)},\qquad
\Pi^*=\left\{\pi:\pi\text{ 满足 }H,\ \sum_a c_{a,\pi(a)}=C^*\right\}.
$$

$C^*$是解释当前返回所需的最小旧绑定改动数，$\Pi^*$是达到该代价的所有解释。没有必要枚举所有匹配。

对actor当前目标行为 $f_*$，定义位置支持集合：

$$
P(f_*)=\{a\in A:\exists\pi\in\Pi^*,\ \pi(a)=f_*\}.
$$

CPU逐个强制候选边、重新求最小费用匹配；最优值仍为 $C^*$ 时，该位置仍可能正确。这样得到全部最优解的目标支持，避免把求解器的单个返回当真值。

若支持不唯一，对合法探针别名 $a$，逐个模拟其可识别行为返回，并在更新后重新求目标支持；选其最坏分支仍可能目标位置数最小的探针。只在当前可行候选内模拟，不用实际隐藏映射。无法辨认的返回必须保留为不会缩小集合的一种分支，不能在规划时假设每个探针都能识别。

同分规则在实验前冻结：先选目标候选里的别名，再按actor旧提示，最后按公开别名顺序。若当前观察没有可行匹配，先检查观察标签是否可靠；不能静默丢弃矛盾或用真实环境映射修图。

一个具体退化情况是：若每个合法探针都可能返回完全无法辨认的信息，而该分支不缩小目标集合，则所有探针的最坏分支值都相同。此时按上述同分规则执行，但不能称选择有信息优势，也不能把unknown分支悄悄删掉。先在dev记录这种并列的比例；若它普遍发生，停止目标探针的效率主张。这是可辨认性成立条件的实际后果，集合保留与单解的比较仍需单独验证。

### 2.4 最小实现与算力

已核验[官方代码](https://github.com/declare-lab/ScrambleToolBench)的`src/agent.py`、`src/env.py`、`src/tasks.py`与`scripts/run_benchmark.py`；执行流程可用API，环境是Python模拟器。匹配部分可用CPU上的线性分配求解器，额外边约束通过重复求解处理，首版只有28个别名。

当前公开`get_agent_class`只接受`default`，不包含原论文的`+ Memory`实现。本地实验需要明确新增一个策略入口，但不能称为复现未发布的原作者memory；下节已完整定义简单知识表控制。原runner还需要在模型调用处计入并执行共同总token上限，这属于预算记账，不能改变某个实验臂的actor能力。

CPU复杂度不等于免费。强制边求解和所有探针分支的次数都要记录；只有API节省大于CPU和额外上下文成本时才称有效率优势。本轮未安装求解器、未运行模型或性能实验。

## 3. 最小验证实验

### 3.1 目的

判断不完整旧图中是否出现“多个等价低代价解释，却任取一个并错用目标”的失败，以及保留集合后调用能否有针对性地消除它。

### 3.2 数据与评测设置

主设置使用官方28个接口、5任务课程，`drift_fraction=.25`；首先不叠加随机故障或window，以隔离映射变化。数值是拟采用的协议设置，不是已运行参数。模型快照、episode数量与费用上限在实验前确定。

自然第一任务不会强制发现完整图。独立离线标注实际已识别行为和旧图完整度，环境真值只用于评价，不能交给controller。另设置在开发阶段固定的partial-prefix诊断，让不同方法从同一份可见历史继续；它与自然end-to-end结果分开，避免人工截断让失败看起来更严重。

所有方法得到相同公开的一一对应结构和“可能局部重命名”提示，不得到实际改变集合或正确工具名称。第一任务探索、后续恢复、失败轨迹与额外probe都计入总预算；不可把前置完整地图免费给主方法。

### 3.3 Baselines（唯一实验baseline定义）

| Baseline | 同任务关系/来源 | 已核验代码或完整本地规范 | 复现路线与控制 |
|---|---|---|---|
| 官方default | 原任务基础行为发现；[论文](https://arxiv.org/abs/2608.02358) | [仓库](https://github.com/declare-lab/ScrambleToolBench)，已读真实default类和runner | `python scripts/run_benchmark.py --backend openrouter --model {共同actor} --agent_type default --tasks 5 --episodes {N} --seed 42 --steps_per_task {cap} --drift_fraction .25`；全部方法共同模型/seed/cap |
| 本地结构化知识表 | 排除只保存显式知识的效益 | 同轮JSON附`memory_update`，按alias存已观察schema/behavior/来源task和recipe；CPU合并，下轮序列化，不做匹配与probe | 在同default策略接口加入该标准表；所有读写产生的输入输出token计费；不是未发布的官方memory |
| cycle tracing | 原论文已有便宜恢复策略 | 目标f旧alias为x；调用x得到f'则沿f'旧alias；找到目标即停，遇缺边/重复/无法辨认则扫未试alias | 同部分旧表、参数和观察；分别比较完整策略提示和CPU跟随版本；不给oracle全图 |
| 单最佳matching | 检验是否必须保留多个解释 | 与主方法完全相同代价和硬边，按字典序取一个最优匹配，照它调用目标；矛盾后更新 | 同CPU接口、actor、图和预算；唯一区别是不计算全部最优边支持 |
| 无旧先验集合 | 检验局部改动先验 | 所有未排除边代价0，保留可行集合，并使用相同最坏分支目标probe | 同数据、合法标签与分支规则；不把未计算概率的策略叫entropy baseline |

以上简单标准算法无需未发布checkpoint、数据或隐藏oracle，可按规范本地实现。源码核验不是实跑结果；所有预算参数待实验阶段冻结。

### 3.4 指标

主指标为episode完成率和平均完成任务数。次指标为全部token、模型/工具调用、CPU时间、第一任务探索成本与后续目标定位的额外调用。

机制指标记录：目标支持集合是否多个、单解选择是否错误、新probe是否缩小目标集合、无法识别观察的比例。使用独立标注或评测环境真值核验，不能把主方法自己的候选图当“实际知识”标签。

### 3.5 支持与失败条件

支持需要同时看到：不完整地图下多个最优解释造成实际错用；集合保留比单解和cycle同预算更少错用/扫描；最终任务成功或完整成本改善。完整地图组只有cycle一样好，是合理边界。

若行为识别不可靠、简单cycle或知识表已等效、局部偏好把真映射长期排在集合之外、只在人工prefix上有效，或CPU/序列化成本抵消工具调用节省，就不能继续宣称方法优势。不能因独立reviewer给8.4分而跳过这些诊断。

## 4. 后续实验计划

1. 在官方不同drift fraction和不同actor上验证，所有baseline每个设置保持同核心参数。
2. 消融旧先验、多解支持、目标条件probe；确认有用的是哪一项。
3. 在同cap下叠加随机超时，检验“没有返回不等于功能失效”的更新边界。
4. 加入更长课程与跨多个边界的patchwork旧图，单独报告识别标签错误与真实映射变化。
5. 对一条自然轨迹展示旧关系、多个最优解释、一次探针如何改变目标位置和实际成功；不要只展示成功特例。

## 5. 风险与开放问题

- **稀疏变化只是偏好。** 最少改动集合可能不含真实映射；新观察必须能提高最优代价，不能无限相信低代价解释。实证失败即止损。
- **行为标签识别。** 一一匹配成立不代表actor可可靠认出行为。无法辨认分支要保留未知；不能免费借真实函数名、输出解码表或额外模型。
- **匿名角色。** 未发现行为不能凭空赋予语义，匹配唯一性可能来自错误命名；先独立检查支持图构造，再测成功率。
- **基准局限。** 人为名称置换比真实API演化窄；本方案不承诺直接支持参数删除、功能变化或真实服务迁移。
- **CPU求解成本。** 不枚举所有匹配，仍有逐边/逐分支重求解；明确测量才可主张低成本。
- **审查地位。** 新的零上下文同家族reviewer认可可进入实验，属于provisional研究判断，不是实验验证或投稿保证。
