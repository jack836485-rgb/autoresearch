## 术语与缩写表

| 术语 | 全称或中文 | 在本方案中的含义 |
|---|---|---|
| ALFWorld / TextWorld | 文字家务任务环境 | agent 通过文字观察和动作完成找物、清洗、放置等任务；本方案不用视觉模拟器。 |
| MemRL | Memory Reinforcement Learning | 固定大模型，用任务结果更新外部经验的数值效用，再按效用检索经验。 |
| episodic memory | 情景经验 | 从过去任务形成的操作经验；这里将文本内容固定，只研究选哪条经验。 |
| cap | 执行上限 | 本次运行最多允许的动作步数；达到它不证明任务永远无法完成。 |
| right censoring | 右删失 | 只观察到任务执行了这么久仍未结束，不知道后面的结局。 |
| competing risks | 竞争事件 | 成功和真正终止失败都是结束运行的不同结局；不能把失败当成可继续等待的成功。 |
| CIF | Cumulative Incidence Function，累计发生函数 | 在指定步数内成功的概率；本方案据此为不同预算选经验。 |
| k=1 | 一次只注入一条经验 | 第一阶段用它隔离多条经验之间的信用归因，防止主张越做越大。 |

## Title

# 跨执行预算的 agent 经验检索：从截断轨迹估计预算内成功概率

**候选 ID：** IDEA-021。**独立审阅：** Call 3，8.2/10，`experiment_ready`，无致命阻塞；这是可进入实验规划的判断，不是性能验证。

**定位关键词：** episodic memory；runtime learning；ALFWorld。

**一句话背景：** 记忆增强 agent 需要从不同执行上限的任务结果中学习，哪些经验能在当前预算内帮助它完成任务。

**本 Idea 的独立创新点：** 区分真正终止与非终止预算截断，用已有不同观察窗口估计经验的预算内成功概率；新增机制是 CPU 上的统计表，不训练 LLM，不追加反事实 rollout。

## 1. 引言式概述

### 1.1 任务锚点与最小范围

先限定文字版 ALFWorld、一个冻结 actor、固定经验库和一次一条经验。任务本身不变，变化的是允许执行的步数。研究问题是：一条经验在短预算下未帮助任务完成后，是否会被标量效用持续贬低，导致在较充足的预算下也被错误弃用？

本方案估计的是“给这条经验后，在 B 步内成功的概率”，不是“这条经验相对于无记忆的因果贡献”，也不是永远能否成功。只在已有观测覆盖的预算范围内做判断。API 推理可以让本地显卡占用为零；仍有 LLM 和 embedding 服务费用。

### 1.2 现有方法怎样处理

[MemRL](https://arxiv.org/abs/2601.03192)把基础 LLM 固定，先按语义筛出候选，再结合数值效用选择经验。公开的 `memory_service.update_values` 给每个被检索 ID 同一条轨迹的终局奖励；其 ALFWorld runner 在步数上限后，将仍未成功的轨迹记作 `success=False`。因此成功、未完成和效用之间存在一个明确的数据通道。

[MACLA](https://arxiv.org/abs/2512.18950)研究程序记忆的可靠性与贝叶斯选择，[AdaMEM](https://arxiv.org/abs/2606.05684)研究不同推理预算下的动态记忆，[UpliftMem](https://arxiv.org/abs/2609.36805)研究相对无记忆的集合级收益。它们分别涉及经验可靠性、预算和价值学习，但本轮查到的材料没有直接覆盖以执行上限造成的右删失记录估计预算内完成分布。

经典 [Time Limits in Reinforcement Learning](https://proceedings.mlr.press/v80/pardo18a.html)早已区分时间上限与自然终止。新意不在重新命名 timeout，而在把这个区分落实到外部经验的学习标签和跨预算检索目标。

### 1.3 具体瓶颈与证据边界

假设经验 A 的操作步骤较长，但在 40 步内通常能完成；经验 B 更短，在 15 步内偶尔成功。把所有 15 步未完成运行都对 A 做统一负更新，可能让 A 在后来的 40 步任务里也被低估。这里的数字只用于解释，没有实验结果。

**已核验事实**是源代码统一处理 `success=False`，以及 runner 存在有限执行窗口。**尚未证实的 failure mode**是这种处理会实际造成跨预算误排序和持续误弃。MemRL 的 G.1 讨论长程更新噪声，但没有直接声称上述删失问题已经被测量。因此论文不能把我们的诊断假设写成 baseline 作者已报告的结果。

还要区分评测与学习：在本次固定上限内没有完成，评测判失败是正确的。本方案不更改成功率分母，只改变这份反馈如何用于其他预算下的经验评分。

### 1.4 我们实际做什么

我们保存每次执行的观察长度与结束原因，为每条经验建立一张按步数展开的完成统计表。成功运行给出成功时点；真正终止失败给出失败时点；预算用完但任务没有自然终止的运行只说明其已观察区间没有成功。

检索时，CPU 查询统计表中当前预算对应的累计成功概率。观察不足则沿用语义排序，不外推未观察区间。actor、经验文本和工具接口保持不变。最小设计不加入新的反思器、世界模型或多 agent 管线。

### 1.5 最小实验概览

在同一 ALFWorld 任务流里，选定经验后随机分配预先固定的执行上限，所有方法共享这份分配规则与总预算。先测短前缀未完成、已有长轨迹后续成功的现象，再比较标量 Q、语义检索、预算分档 Q、跳过截断负更新和完成分布检索。冻结学习结果后，在各个有数据支持的预算下比较成功率和误弃情况。简单对照已经解决问题时，就否定复杂机制的必要性。

### 1.6 拟验证的贡献

1. 一种无需模型训练、使用可观察执行事件的预算条件化经验效用估计。
2. 一项区分“上限内失败”和“可迁移经验无效”的诊断，以及简单替代解释的对照。
3. 一个在相同模型、任务、经验与完整预算约束下可复现的实现和分析产物。

这些是拟验证贡献，当前没有任何性能结果。

## 2. 详细方法计划

### 2.1 方法直觉

“没有看到它完成”只对已经观察过的步数提供信息。实际流程如下：

1. 从固定经验库按同一个语义检索器产生候选，选择一条经验给 actor。
2. 构建阶段在选择后随机分配执行上限；不能因为判断它快失败了才缩短窗口。
3. 原 actor 正常执行，记录动作步数、公开环境结果及停止原因。
4. CPU 更新经验的每步在险数和成功/终止失败事件数；预算截断只结束观察。
5. 冻结后，对当前预算查询成功累计概率，选择有观测支持且预期合适的经验。

### 2.2 输入、输出与成立条件

- 输入：任务类别、固定 memory ID/内容、语义候选、原 actor 轨迹、观察步数和可区分的停止事件。
- 输出：每条候选在指定步数内的成功概率，以及选中的一个 memory ID；模型照常输出动作。
- 成立条件：执行上限在选定经验后独立随机分配；停止事件有可信日志；同一任务族中的观测足够可比；查询预算有训练观测支持。

LLM/embedding 服务调用错误不应伪装成环境终止失败。环境本身的时间限制也必须与实验外部上限区分。若日志无法判断某次运行属于哪种结束原因，就不能用它更新需要该标签的统计量。

### 2.3 统计量与检索规则

先用文字解释，再给最小公式。对一个 memory 和一个固定任务族，把在第 u 步之前尚未成功、尚未真正失败且仍被观察的运行计为“在险”；在第 u 步发生成功或真正失败的分别计数。预算截断记录在截断后退出在险集合，不被当成失败事件。

令 $m$ 为经验 ID，$g$ 为公开任务族，$u$ 为动作步数。$Y_{m,g}(u)$ 是第 $u$ 步之前仍在险的运行数；$d^S_{m,g}(u)$ 和 $d^F_{m,g}(u)$ 分别是此步的成功与真正终止失败数。它们都来自可见执行事件，不读取任务答案。

$$
\widehat h^S_{m,g}(u)=\frac{d^S_{m,g}(u)}{Y_{m,g}(u)},\qquad
\widehat h^F_{m,g}(u)=\frac{d^F_{m,g}(u)}{Y_{m,g}(u)}.
$$

这两项表示仍在执行的运行，在该步以成功或真正失败结束的比例；只有在险数非零时计算。

定义 $\widehat S_{m,g}(0)=1$，并令

$$
\widehat S_{m,g}(u)=\prod_{v=1}^{u}\left[1-\widehat h^S_{m,g}(v)-\widehat h^F_{m,g}(v)\right],\qquad
\widehat F^S_{m,g}(B)=\sum_{u=1}^{B}\widehat S_{m,g}(u-1)\widehat h^S_{m,g}(u).
$$

$\widehat S$ 估计仍没有以任何自然事件结束的概率，$\widehat F^S(B)$ 估计 B 步以内成功的概率。这里沿用已有竞争事件估计思想，不把统计公式声称为新发明。若本环境子集只有成功与预算截断、没有可识别的真正失败事件，相应失败事件计数为零。

检索仍先经过与 baseline 相同的语义候选筛选，在有足够观测支持的候选中按 $\widehat F^S(B)$ 排序；不足时采用原语义顺序。候选支持阈值和任务族粒度只在 dev 冻结，所有简单对照用相同信息范围。不得在没有长观察记录时预测更大预算内的成功率。

**统计边界：** 在同族中经验被用于不同难度任务，仍可能有选择偏差。本方案不宣称解决全部记忆因果归因；初始诊断应在共同任务/候选支持下做配对比较，并单独报告低支持样本。更细的任务条件模型不进入首个最小实现。

### 2.4 最小实现与算力

以 [MemRL 官方代码](https://github.com/MemTensor/MemRL)为起点：ALFWorld runner 记录停止原因与步数，MemoryService 增加 CPU 事件表，retrieval 将标量值查询换成指定预算的概率查询。保持原 actor 调用路径和 API embedding。初始经验由共同的 train 轨迹形成，所有组承担相同构建成本。

首个固定库实验冻结经验内容及 ID，只更新效用；这是一项明确的受控设置，不能把它的结果直接称为整个原生 MemRL 的完全复现。通过后再做统一的新经验写入设置。API 方案无本地 LLM 权重、反向传播和 GPU 训练；文字 TextWorld 在 CPU 运行。Linux/WSL2 是优先复现环境，Windows 原生依赖能否直接安装尚未实跑。

## 3. 最小验证实验

### 3.1 目的

先判断误罚通道有没有实质影响，再判断完成分布估计是否比最便宜的修法更好。两个判断任何一个失败，都不能继续宣称新机制必要。

### 3.2 数据、切分与预算安排

使用 ALFWorld 的 TextWorld 任务，保留原始 train / seen / unseen 角色；train 获取共同经验与学习值，dev 冻结预算档、支持阈值和统计粒度，held-out 测正式效果。任务 ID、任务族比例及顺序在运行前一次固定，测试答案或未来轨迹不进入在线更新。

构建阶段用若干不同执行上限，cap 在记忆选定后随机分配。各实验臂共享任务、上限抽样和 seed；策略不同产生的实际轨迹不必相同。较长 cap 的代价记入所有组同一总预算，不能给本方法独占长轨迹，再给 baseline 只看短反馈。

用于说明的候选预算档可为 10/20/40 个动作；**这还不是运行参数**。实际档位应根据公开任务长度和用户预算在实验计划阶段确定，且不得只挑恰好让本方法获益的区间。模型快照、调用金额上限和样本数同样尚待用户确定。

### 3.3 Baselines（唯一实验 baseline 定义）

| Baseline | 同任务关系与论文 | 已核验实现/规范 | 具体复现路线 | 核心控制 |
|---|---|---|---|---|
| 固定库 MemRL 标量 Q | ALFWorld、冻结 actor、经验效用；[论文](https://arxiv.org/abs/2601.03192) | [代码](https://github.com/MemTensor/MemRL)；已读 `run/run_alfworld.py`、`alfworld_rl_runner.py`、`memory_service.update_values` 与 YAML | `python run/run_alfworld.py --config configs/rl_alf_config.yaml`；共享初始库并冻结内容写入，只保留原标量值更新；清楚标记受控版本 | 同一模型/embedding、候选、k=1、任务/seed/预算分配 |
| semantic-only | 相同库的语义检索，排除新记忆内容收益 | 同仓库已读 query retriever 与 value-driven 开关 | 同 YAML 设 `experiment.enable_value_driven=false`；相同候选与 k | 与主实验共用 actor 和执行窗口 |
| 预算分档 Q | 排除只是把预算加成条件的解释 | 标准可直接本地实现；每个 memory/任务族/预算档沿用同一奖励均值更新，不作删失修正 | 替换 CPU 数值表；未知档不外推；档位与主方法相同 | 相同反馈、预算档、构建和查询成本计入 |
| skip-update | 排除只是避免给截断轨迹负更新的解释 | 标准可直接实现：仅当 runner 明确预算截断且环境未终止时跳过 Q 更新，其余保持原规则 | 使用相同事件日志，不新增模型调用 | 相同候选/k/任务与 cap |
| 无记忆 ReAct | 检查记忆投入是否比直接执行更值；[ReAct](https://arxiv.org/abs/2210.03629) | 同一 runner 不注入 memory 的标准 agent；保留原 few-shot 与工具 | 只删除 memory 注入；可把省下的记忆开销用于动作，仍受统一硬预算限制 | 同 actor、任务和逐任务工具/token/调用硬上限 |

源码“核验”指已打开并确认实现和入口，**没有安装或运行验证**。MACLA/AdaMEM 是已读相关工作，不被伪装为本次已运行 baseline；完整论文比较前需先核验其同任务代码和预算接口。UpliftMem 未找到可核验原作者实现，因此只作最近相关工作，不纳入这次最小实验。

除上述刻意改变的效用机制外，锁定模型快照、推理模式、temperature、top-p、seed、初始经验、候选集合、k、任务族、task IDs、cap 分配、最大输入输出 token 和工具调用上限。memory 构建、embedding、反思或检查的 API 成本全部计入，不能只算 actor。

### 3.4 指标

主指标是在每个已覆盖预算下的 held-out 任务成功率，报告任务族分层及配对差异。总体分数按预先冻结的预算/任务族权重汇总，不以最有利档位替代总体结果。

诊断指标为短前缀未完成但长记录后续成功的比例、这些记录触发的负更新量，以及冻结后经验排名与预算内实际成功率的吻合程度。“误弃”只对具有独立长观察证据的经验/任务对定义；不能用本方法自己预测的成功率作真值。

次指标为全部输入/输出 token、LLM 与 embedding 调用数、动作数、API 费用、CPU 时间与事件表大小。效果不以 CPU 很小替代 LLM 成本公平。

### 3.5 支持条件和失败条件

值得继续的结果应同时满足：出现可重复的跨预算误排序；同预算下新方法改善成功率或概率校准；改善超过 skip-update 与预算分档 Q；且没有靠更多调用、未来反馈或外推完成。

如果误排序很少、自然长记录不足、最便宜的 skip-update 已完全解决、细分后样本太稀疏，或额外随机预算获取的成本抵消收益，就应停止此机制。统计区间跨零时如实写证据不足；不把 reviewer 8.2 分当成实测支持。

## 4. 后续实验计划（仅最小实验通过后）

1. 扩大 ALFWorld seen/unseen 与任务族，加入同样冻结库和完整预算控制的已核验程序记忆方法。
2. 消融删失标记、预算条件、真正终止失败事件和语义 fallback，检验每一项是否必要。
3. 在相同每臂参数下比较不同 actor；每个 actor 独立学习值，避免把模型强弱当方法收益。
4. 恢复所有组相同的新经验写入规则，观察固定库结论能否延续；k>1 单独作为后续扩展，不提前承诺解决组合信用。
5. 展示一对可读轨迹：短窗口在哪一步被截断，已有长窗口怎样完成，哪些负更新导致后续误排，校正是否实际改变检索和结果。

## 5. 风险与开放问题

- **预算截断可能是原任务目标的一部分。** 本次评测仍把 cap 内未完成判失败；只有跨预算学习标签需要区别，不能偷换成“原指标错了”。
- **经验可能太少被重复使用。** 原始逐条 memory 的统计表会稀疏；先在有共同支持的固定库检验，若支持不足，不能靠无限追加轨迹掩盖问题。
- **随机窗口条件可能不成立。** 若 cap 或人工停止依赖已看到的危险/失败征兆，简单删失估计会偏；首个实现只用独立随机外部上限。
- **执行机制会随预算提示改变。** 构建阶段 actor 输入固定，不额外告知不同 cap；如果之后研究 budget-aware actor，必须重新检验估计目标，不能沿用本轮保证。
- **观测混合仍不是因果价值。** 单条记忆与任务难度仍有选择关系；本方案不承诺无记忆 uplift，需将比较范围限制在共同候选/任务支持内。
- **新意尚属可实验判断。** Reviewer 同属 OpenAI 模型家族、使用新零上下文审阅；新意结论是 provisional，不等于会被投稿审稿人接受。
