## 本轮补充核验（主执行器，2026-11-02）

以下内容由主执行器直接读原文或代码仓库核验，用于生成候选；不传给 reviewer。

1. **2605.24202 v2（arXiv，2026-05-31）细节**：Qwen3 LoRA，GRPO 无 KL，clip-high 0.28，组大小 8；所有角色收到同一个结局奖励（broadcast），按角色只在自己 token 上累积梯度。§5.1 明说 gradient_amplification "adds more same-role updates per iteration"——并行同角色实例共享一个 adapter 时每个训练步多走优化器步。附录 Table 3：SA-RL 适配器只放到生成角色、其余角色用基座时，1.7B 数学 Orch-Workers 为 58.9，高于 MA-RL IP 的 55.5；Voting 50.5 对 50.9；Eval-Opt 49.1 对 60.0。
2. **作者已更新的版本（GitHub `XHMY/marl-llm-workflows`，项目页同步"2026-11-01 版论文"，arXiv 尚未更新）**：
   - 新摘要："Single-agent RL in the same structure matches or beats trained Voting and Orch-Workers, and within the grid only Eval-Opt under IP exceeds it."
   - Eval-Opt 的增益主要来自评估者把截断的首答退回重试；固定"截断即重试"规则在 1.7B/4B 复现大部分增益，更长的单次 SA-RL 回答在较大规模补上大部分差距。
   - 独立策略的后期下降：并行角色每个实例走一个优化器步；单角色对照（无工作流）与逐投票者奖励对照也下降；合并为每步一次优化器更新（`t2_merged_minibatch`）可推迟下降。
   - 共享策略学得慢：逐输出 token 平均使短输出的决策角色占据过多梯度份额；按角色长度重加权后共享策略获得 IP 的速度与峰值，也随之下降。
   - 仍是每个格子一个种子；只有数学与代码；无工具使用工作流。
3. **Dr. MAS（2602.08847 v2）**：数学（solver+verifier）与多轮搜索（verifier/search/answer 三角色，均可见全部历史）。Qwen2.5-3B 搜索平均 avg@16：单智能体 GRPO 32.5，多智能体共享 GRPO 34.8，非共享 GRPO 34.5；按角色归一化主要修复 7B 非共享的崩溃。对照是"单智能体一个回答"，没有"单智能体 RL 放入同一结构"。代码 `langfengQ/DrMAS` 含搜索与数学编排。

## Problem Anchor（冻结）

- **Bottom-line problem**：多智能体 LLM 工作流做端到端 RL 时，相对同任务的单智能体 RL，联合训练的增益何时为正；独立策略后期下降的原因。
- **目标领域与设置**：多智能体 LLM 工作流的结局奖励 RL（GRPO 类），共享策略 vs 独立策略；卡片证据的设置为 Qwen3 0.6B–4B、数学与代码、Eval-Opt / Voting / Orch-Workers。
- **Must-solve bottleneck**：卡片"尚未解决"——多种子与工具使用工作流下是否成立。
- **约束**（来自用户 AGENTS.md）：
  - 预研 2×A100 80G / 4×L40 48G / 8×4090 24G；正式实验 8×A100 80G，单次运行最好不超过 5 天；
  - 付费 API 1000 元以内可自主决定；token 稀缺；
  - 目标：自 2026-10 起半年内投一篇主会；
  - 不同 baseline 的核心参数需一致（控制变量）。
- **非目标**：不在本 skill 内跑正式实验；不做安全攻防类设计。
