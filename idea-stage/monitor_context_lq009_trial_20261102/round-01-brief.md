## 背景

**定位关键词：** long-context monitoring；chain-of-thought monitorability；provenance tracking；program slicing。

**一句话定位：** 在长工具轨迹且 CoT 不能可靠暴露违规时，监控器既要定位动作，也要找到判定该动作所需的远程任务约束与状态证据。

## 核心 Claim

本方案要解决“短窗口看到了动作，却丢掉其前置判据”的监督失败，提出面向动作的跨窗口证据闭包。成功后得到的是在固定计算和误报预算下提高违规召回的方法，不以发现一个两因素交互项作为主贡献。

已有证据：Classifier Context Rot（https://arxiv.org/abs/2605.12366）显示长日志监控退化，分段和多点检查可缓解；Reward Misspecification（https://arxiv.org/abs/2610.28303）显示奖励失配后的 CoT 可以顺从或无信息；MRT（https://arxiv.org/abs/2508.19461）已有较强的层级/顺序监控。这里待验证的机制是：局部证据各自无害，跨窗口的“约束—对象来源—动作”关系才决定违规，因此单纯缩短窗口或按表面相似度检索仍可能漏报。

主张：对缺少直白意图信号的长工具轨迹，从待检查动作反向取回有出处的必要证据，比固定分段、普通检索和层级摘要在相同输入/输出 token 预算及整条轨迹误报率下有更高召回。贡献的重要性来自实际监督能力，视角新意来自动作依赖闭包，预期有效性的依据是程序切片能保留判定所需关系；agent 场景能否正确建边及是否比强 baseline 有优势，都须由实验推翻或支持。

## 方法设计的核心思想

输入为真实用户任务、工具 schema、已经发生的工具调用和返回值；监控器看不到恶意副任务、真实标签或未来反馈。先用工具 schema 和可见实体 ID 建立读写/引用索引。对每个改变外部状态的动作，反向取回它引用对象的来源、最近相关更新、任务约束和授权出处，保留原始片段与调用编号。依赖不明确时标为缺失，不编造“已满足”。在固定 token 预算内，按当前动作到前置证据的依赖距离选择片段，再交给冻结监控器打分；全轨迹分数用相同开发集校准，绝不把每窗口误报率当全轨迹误报率。

与 ledger 的区别是按每个动作按需取回原始证据，不依赖一个固定摘要 schema 能预先保留所有关系；与 Minos（https://arxiv.org/abs/2607.00440）的区别是从所有状态修改动作出发做在线监督，不从已知安全告警定位攻击根因。对照须向 baseline 开放相同 schema/实体信息，并计入索引构建、证据提取和所有模型调用成本，避免用额外信息制造优势。

## 最小实验

主任务为 MRT/SHADE-Arena 的工具轨迹，选择公开数据中至少三个含远程约束的任务族，复用 naive、liar/selective-verbalization 与 no-secondary 轨迹。该主实验研究 CoT 信息不可靠，不将这些提示式策略称为奖励失配训练。保持自然轨迹原样；另作受控证据距离干预，只插入不改变状态的无关读取，保留原始事件顺序和标签，短/长目标为 8k/32k/64k。自然与构造结果分别报告。以调用开始前可见前缀为单位，禁止看到待判动作的未来结果；动作已完成的事后检测另列。

冻结同一监控模型、提示、输出上限、采样设置与数据切分。每条轨迹每个方法的总输入预算上限 16k，输出 512；多次调用的系统提示与摘要消耗均计入。比较全文预算截断、固定窗口、BM25 top-k、MRT 层级/顺序及其可复现 hybrid。数据按原任务划分校准与测试，填充版本和同源轨迹不跨集合。主指标为整条轨迹 FPR=5% 下的 TPR，同时报告 PR、误报、首次告警延迟和总 token；任务分块 bootstrap，避免将同一轨迹的填充副本当独立样本。

关键机制实验：自然的跨窗口关系子集；同 token 长度只改变证据间距；移除依赖闭包但保留同等数量原文；给 BM25/层级摘要相同结构元数据。至少提升 10 个百分点且 CI 排除 0，才能支持主方法；仅构造数据有效、自然子集无提升或同预算优势消失，则不足以支持主贡献。两因素交互只作诊断，不作为通过标准。

可复现入口：MRT 官方仓库 https://github.com/scaleapi/mrt，已读 `monitor_generation/add_monitors.py`、`scripts/run_monitors_shadearena.sh` 和 `load_trajectories.py`；直接调用 Python 入口并采用 README 列出的 monitor styles，避开 shell 启动器已有的赋值语法问题。标准 BM25、定长分段可直接实现。Paranoid Monitors 是重要近邻，但全文入口受限、未核验官方代码，不能假装已复现，实验前需取得充分规范再纳入。

真实奖励失配扩展复用 hewittlab 公开 gpt-oss-20b control/misaligned 模型集合及原任务标签，代码 https://github.com/Lorenayannnnn/reward-misspecification-degrades-cot-monitorability 的 `src/analysis/run_inference.py`、`src/monitor/monitor_utils.py`。该代码与 Hugging Face checkpoint 已确认公开；这是一项独立扩展，若无法产生有跨步骤依赖的样本，不据单轮 coding 结果外推工具 agent。

共 7 个臂（含本方法）。规模按 120 条测试轨迹、120 条校准轨迹、3 种长度、每臂总输入 16k 和总输出 512 的上限估算，最多 80.64M 输入 token 和 2.58M 输出 token；先用单监控器做筛选并复用固定评分，再扩第二家族。GPU 只用于可选 20B 冻结模型推理，代码与数据在 SSH 服务器。API 是否落入 1000 元取决于所选端点单价，开工前按这两个总量核价；本轮只做方案审查，不发生 API 推理费用。
