## 背景

**定位关键词：** agent monitoring；long-context classification；false positive rate。

**一句话定位：** 冻结 LLM 检查长 agent 转录时，如何知道本次读取漏掉了已有证据，并把有限重读预算用在合适的方式上。

**与起点问题的关系：** 子问题，针对长输入导致的证据利用失败；不承诺恢复奖励失配后根本不存在于 CoT 的信息，原卡的真实奖励训练 × 长转录交互仍未回答。

## 核心 Claim

提出一个黑盒、无训练的重读预算分流方法：用同次长转录的影子阳性对照，而不是模型自报置信度，选择分块重读或全文复读。在总输入/输出额度相同、整轨迹误报率相同的条件下，它应比固定分块、重复全文、随机分流和自信度分流获得更高的真实攻击召回。

当前依据：Classifier Context Rot 的同攻击长度/位置干预说明，有些失败来自读取已有证据的能力下降，而非标签变化（https://arxiv.org/html/2605.12366v1 §3–4）；SLEIGHT-Bench 提供跨盲点的成对攻击/良性转录和提示式监控规范（https://arxiv.org/html/2605.16626v2）。已知正对照能观测某种读取失败，但它能否预测另一处真实证据的遗漏、是否比自信度更有用，仍未知。不能用正对照检出率本身冒充真实攻击收益。

## 方法设计的核心思想

先对原始日志作一次全文监控。随后复制到隔离的影子输入，在随机位置加入从开发集构造的一个自包含、已知违反监控规范的动作片段；ID 格式与普通动作一致，监控器不获知对照位置或标识。影子监控器按同一规范列出可疑动作及 ID；脚本只取已知对照片段是否被指出，不把影子内任何新增报警算作原始日志的检出。

若对照漏检，剩余额度用于把原日志分成四个顺序块分别监控；若对照检出，剩余额度用于另一轮原日志全文监控。最终只合并对原始日志的判断；正对照不能直接让目标报警。所有对照生成、影子读取及重读成本均记账。对照库只来自训练/开发部分，与测试攻击及其良性配对隔离；对所有分流方法开放同一开发资源。

## 最小实验

用官方 https://github.com/safety-research/sleight-bench 的 40 个攻击及成对良性变体作有限压力测试。官方数据加密但公开解密密钥；已核对 `FORMAT.md`（tool_use/tool_result、metadata 分离）与 `experiment_paper.yaml`。不把 metadata、攻击标签或真实危险位置交给监控器。以原攻击及所有变体为一个组做交叉拟合划分；阳性对照库不得取自测试原攻击。良性填充只由开发良性转录拼接，构造 8K/32K/64K 三种输入并随机位置，明确这是合成长度干预，不能据此声称自然部署收益。

固定同一 gpt-oss-20b 监控器，官方 config 为 https://huggingface.co/openai/gpt-oss-20b/raw/main/config.json，context 上限 131072。采用官方 ControlArena 监控规范并适配到同一模型；不冒称复现原文 frontier 模型成绩。全文、固定分块、全文复读、随机分流、自信度分流和本方法均享有每条最多 3L 输入、3072 总生成 token 额度（包括中间调用；对照构建按所有样本分摊），相同温度与种子；每项选择成本计入。固定分块和复读可用满相同额度。只宣称比较提示式冻结监控；不宣称超过有额外文件工具的 agentic coding monitor。

主结果是总 token—整轨迹召回/误报曲线和留出攻击组上的差异区间；先看影子漏检是否在控制长度/位置/首轮分数后仍预测真实漏检，再看分流是否优于最强固定策略。80 条成对记录不足以精确校准 1% FPR，因此主报 ROC、10% 工作点及其宽区间，不承诺可靠低误报部署。若影子信号无增量、收益来自更高误报或更大预算，或固定分块更优，则主张失败。

主设置约 80×3×6×3×平均35K ≈151M 输入 token，外加开发选择和不超过约4.4M生成 token；同源变体不当独立样本。冻结推理可用预研 A100，扩展上限 8×A100/5天，开工前测吞吐；这里没有假定已跑出耗时或效果。本轮只打磨，不启动推理实验。
