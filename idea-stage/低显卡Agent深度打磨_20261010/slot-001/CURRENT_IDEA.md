# 诊断等价而恢复不等价的工具计数任务

本 Idea 提出受控评测任务，检验冻结 agent 在已经得到正确计数诊断后，能否选择有作用的恢复操作，并区分预算不足与公开能力不可达。独立 Review 第8轮评分7.7、无 fatal blocker；Q001、Q005各完成10个有效独立循环。没有执行正式实验，以下均为待检验设计，不表示已经发现发生率、解决问题或提升性能。

## 术语表

| 术语 | 中文含义与实际作用 |
| --- | --- |
| actor | 冻结的执行模型；读取同一任务、公开工具文档和真实返回，选择调用或终止 |
| eq / gte | 公开计数限定：精确值／下界；eq仍须结合覆盖与超时信息解释 |
| 支持性完成 | 当前公共历史一致的所有世界都支持同一精确结论，同时该结论符合实际任务 |
| 诊断等价配组 | 本方案的任务定义：固定用户精确目标、当前公共证据及正确不足诊断，改变公开工具作用和预算 |
| 能力阻断 | 在指定公开动作闭包内，即使放宽预算，也不能获得支持所需结论的证据 |
| 预算阻断 | 公开动作存在支持性恢复策略，但指定剩余预算不能执行它 |
| AND/OR策略参照 | 标准条件规划：动作是OR选择，实际返回分支是AND条件；用于能力参照和离线标签，不是新算法 |

## 1. 初始目标、研究变化与当前目标

初始Q001关注格式正常的工具语义错误在传播前的识别与有限交互恢复；Q005关注正确诊断与可执行修复之间的差距。初始不足为Q001-D01、Q005-D01及Q001-D02（诊断调用同时改变受扰动状态）。pre_solution_idea原值为null，本方案没有沿用初始方案。

机制迁移与近邻改进中，残余过滤、例子驱动查询修复、加权校验、类型／生命周期控制等已有重合。本方案最终聚焦到Route3的具体任务贡献：正常计数限定被加强为精确结论，以及正确识别不足后仍选择无效精化。它声称处理Q001-D01、Q005-D01及新不足S001-N02、S001-N03；addressed表示设计了验证，不是实测解决。first-touch状态通道和一般工作流恢复仍未覆盖。

真实接口支持该聚焦：[Elastic Search API](https://www.elastic.co/docs/solutions/search/the-search-api)的Track total hits定义下界与精确值，同页超时例子仍可返回eq；[ToolUniverse审计](https://arxiv.org/html/2609.26836v1)已讨论限定丢失、用途适配及更强结论传播。这些事实提供任务来源，其本身不是本方案创新。

## 2. 背景、失败条件与已有处理

例如，value=100、gte意味着N至少100，不能直接报告精确N=100。value=100、eq同时伴随部分覆盖，也不能直接证明全任务范围的N=100。即使agent正确判断“当前证据不足以支持精确总数”，下一次请求仍可能只升级已处理部分的精度，或重复读取同一范围，无法补齐缺失分片。

已有恢复诊断、公开工具提示和成本规划并非空白：[PROBE](https://arxiv.org/html/2605.08717v2)给出有界恢复指导及执行范围限制；[Outcome Monitors](https://arxiv.org/html/2608.19303v1)已经分离诊断细节和恢复工具列表；[DARC](https://arxiv.org/html/2608.11772v1)已有冻结任务族诊断、干预限制与成本感知恢复。当前剩余问题是能否通过固定当前正确诊断的episode配组，分开操作语义错误、预算不足和能力不足，而非再次证明“诊断不保证恢复”这一总体命题。

## 3. 核心Claim与可证伪预期

待检验的独立任务Claim：固定正确的计数不足诊断、用户精确目标与当前公共证据，公开动作作用和剩余预算仍能使实例分别处于支持性可恢复、仅提高预算后可恢复、公开动作闭包不可恢复三种状态。评测要求agent选择有效首动作或给出有据的阻断判断，检验正确诊断反馈是否仍留下系统性的操作作用与可达性混淆。

**gte／正确不足诊断配组仅含上述后三类。完整eq的无需修复实例是单独干净对照，不能称为同gte诊断组的第四终态。**

支持该任务价值需要在budget-sufficient配组中，保持诊断、文档、操作范围和核心模型相同，仍观察到修复动作错误，并由完整公开语义参照解释对应原因。如果提高预算能解释全部错误、正确诊断已消除差距，或差异只由反馈多寡、隐藏能力、遗漏说明或不公平成本产生，则该任务Claim受限或被推翻。区间传播、AND/OR规划、冻结诊断与一般能力改变可恢复性均不申报新颖。

## 4. 任务与参照策略设计

每个episode输入是用户精确计数要求、初始Search结果、公开分片范围与各片可能计数域、工具适用范围／转移语义／费用及剩余预算。成功工具返回没有假记录或重复计数；部分非负计数可作为下界。任意数字污染会破坏此假设，不属于本任务。

环境是CPU可实现的有限静态计数世界。当前历史H限定可能世界集合Ω(H)，其中每个世界都满足已经公开的数值与覆盖信息。完成时报告N*的支持条件为：对每个w∈Ω(H)，N(w)=N*。因此，刚好猜中隐藏N也不能获得支持性完成标签。隐藏实际世界、评测终态与可达标签不进入在线actor。

正确诊断只由公开限定和当前可能计数是否仍不唯一生成，例如“目前是下界，不能支持精确总数”。它不读取隐藏故障原因。方法收到的公开文档与可调用工具相同；文档重排只重新组织已经提供的内容，不附加最优动作答案。

标准语义参照依据公开动作效果和实际返回更新Ω(H)，在指定成本模型和剩余预算中枚举有限条件策略。动作后的所有可达公开返回分支都须支持最终结论。离线evaluator保存最小可行成本、有效首动作集合以及能力／预算阻断标签，不能让oracle按隐藏真实世界选择不同首动作。在线强参照可以从同一公共信息推导策略，但不能读取这些离线答案。

预算可达标签只对明示成本模型成立。规划、诊断和actor费用须在统一账本中计入；单看最少工具调用费，不能称为包含推理开销的最小总恢复成本。具体计费模型和预算参数在实验规划时确认。

## 5. 最高近邻与独立差别

| 已核实来源 | 已覆盖关系 | 本方案保留的窄差别 |
| --- | --- | --- |
| [Limbo](https://arxiv.org/html/2609.29095v1) §3–5 | 同故障换合同、观察等价、读回能力与不可恢复边界 | 当前是固定正确计数诊断和公共数值的配组，不是新的合同恢复机制 |
| [DARC](https://arxiv.org/html/2608.11772v1) §3–4、§6.2 | 诊断限定干预、成本策略、信息匹配的diagnosis-only对照 | 当前episode级的精确计数支持性与能力／预算阻断标签 |
| [CostBench](https://arxiv.org/html/2511.02734v1) AppB.2、B.5 | datatype单调规划、费用、禁用工具及保留可解图 | 当前终点是公共证据支持精确结论，允许动作闭包不可达；不申报成本规划算法 |
| [Outcome Monitors](https://arxiv.org/html/2608.19303v1) §3、§5 | 公开诊断、恢复工具列表和分解控制 | 当前固定诊断后检验完整动作作用与预算可达性，不是提示多列工具 |
| [SearchJev](https://arxiv.org/html/2610.05107v1) Table1、AppD.3 | 充分性、下一动作、支持性判断；typed菜单可扩展 | 当前有实际工具转移和成本的闭环配组；不声称其架构不能处理恢复 |
| [UndoBench](https://arxiv.org/html/2610.05622v1) §2.2、§5 | 可见返回与状态效应分离、配对恢复及阶段依赖 | 当前静态只读计数任务与其mutation边界不同；一般恢复能力分解已覆盖 |

第8轮Review批准的是这一具体任务贡献，评分7.7、无fatal blocker；它不支持算法创新、普遍恢复能力提升或未运行结果。[Failing Tools](https://openreview.net/pdf?id=j7YsSnA64D)的原站索引可读，全文及情景附录受到challenge／403限制；不能完全排除同构任务，也不能宣称全领域无人做过。

## 6. 最小验证与可复现性

主要配组固定用户“报告精确N”、当前value=100/gte及相同公共分片界，并公开改变能力实例。下面的3、4等数值只沿用Brief的示意费用，不是测量值或默认实验参数。

| 公开能力实例 | 操作作用 | 要测的区别 |
| --- | --- | --- |
| A | exact_all一次获取完整精确总数，示意成本3 | 能否直接执行支持性恢复 |
| B | exact_part只覆盖指定片；其余公开读取累计完成，示意总成本4 | 不能把局部精度提升当作完整覆盖 |
| C | restore_endpoint后读取缺失片，示意成本1+2 | 恢复前置状态与直接重试的区别 |
| D | 不确定分片没有任何公开读取／恢复入口，其公共可能总数仍不唯一 | 能力阻断不能靠更大预算补齐 |

每种能力在充足与不足预算条件重复；完整eq另列干净对照。有限世界、初始公共证据和操作效果必须相容；D中的“不可达”来自非单点不确定性和公开动作闭包，不能仅因为未知片计数非零就判不可达。

同任务对照包括：普通／failure-aware FunctionCalling、公开正确诊断coaching、已有文档相关段落重排、只升级精度、盲重复同调用、泛化forced-continue、同actor typed-menu接口与完整公开语义参照。普通actor的[实际实现](https://raw.githubusercontent.com/Zhudongsheng75/ToolMaze/main/evaluation/agents/openai_agent.py)已核实调用循环、结果回送与token统计；移植到完整定义的新CPU任务，不冒称复现原ToolMaze数据或最高近邻整套系统。

[SearchJev inference源码](https://raw.githubusercontent.com/EvoScientist/SearchJev/main/training/inference.py)已核实任意state、question和choice菜单；同冻结actor的标准菜单对照用于接口比较，不等同训练版SearchJev复现。简单标准策略由上述完整定义实现；纯确定性参照与同actor载体分列，不把少用模型的控制器结果归因于模型能力提高。

全体配组报告支持且正确完成、有效首动作、正确能力／预算阻断、无效重试成本、错误完成与干净损失。正确诊断子集单列恢复指标，同时保留完整分母和筛选规则，不由分类汇总率相除得到条件恢复率。主比较固定同核心actor、解码、任务、公共文档／操作范围和总预算上限；token、工具、扫描、CPU、文档处理、诊断、规划、重试和等待全部计费。重复与统计功效须在实验规划时冻结。

## 7. 未覆盖目标、边界与交接

本方案未处理Q001-D02的first-touch通道、隐式任意数字污染、动态数据漂移、外部写入的不可逆恢复或一般工作流修复。初始工具语义错误在这里收窄为限定被加强及公开计数支持不足，并不覆盖所有正常格式错误。

邮件读取分支的Seen／UID／PEEK关系及选链历史仅留在候选池与原始审查中；其第9/10轮均为探索性7.2，没有通过资格，也不用于证明本方案或加入新组件。该分支的成熟直接路由与公开系统实现边界已保留。

下一步仅为实验规划。核心模型／方法、有限世界规模、动作费用与统一预算账本、样本量、重复次数及统计功效待用户确认。本阶段没有正式实验、实验代码或付费推理调用；Review通过是选题判断，不是结果支持。
