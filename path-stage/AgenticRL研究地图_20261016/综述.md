# Agentic RL 近半年进展综述（2026 年 4 月至 10 月）

检索日：2026-10-16。窗口：2026-04-16 至 2026-10-16。机构口径与证据粒度同 [研究地图.md](研究地图.md)：厂商白名单加 QS 2027 前 50 高校，其余标为背景；论文以摘要和正文前部为据，技术报告只读了相关段落，数值未与原文表格核对。文献编号与研究地图一致，本文新增的作品从 [38] 开始。

## 1. 什么是 agentic RL，它和单轮推理 RL 有何不同

Agentic RL 指在多轮交互环境中，用强化学习训练 LLM 或 VLM 智能体：模型每轮输出动作（工具调用、命令、点击、搜索），环境返回观测，奖励通常只在任务结束时由验证器给出。典型任务包括 SWE 与终端编码、深度搜索、网页与 GUI 操作、API 工具链和交互式文本环境（ALFWorld、WebShop、AppWorld、τ²-bench 等）。

近半年的工作反复显示，它与单轮推理上的可验证奖励 RL（RLVR）有三点实质差别：

- **观测由策略自己产生。** 闭环 agent 后期遇到的状态部分由它早先的动作决定，SFT 与 RL checkpoint 即使做同一任务，也是在不同状态下被评分 [27]。
- **训练动态不同。** 单轮推理 RL 的熵通常塌缩后保持低位，agent RL 则出现周期性的熵爆发与回落 [9]；仅任务时程变长就足以引起严重不稳定 [13]。
- **能力边界的结论不同。** 静态推理文献认为 RL 主要在基础模型已有能力内重新分配概率；而在需要组合式信息收集的工具任务上，RL 的 pass@k 曲线在大 k 端仍高于基础模型且差距扩大 [28]。

## 2. 主流训练流程：技术报告怎么做

本轮读到的大厂报告呈现出相近的流程，以下只列报告原文明确写出的内容：

- **可执行环境中的大规模 RL。** Kimi K3 把 RL 扩展到三大类领域，而不是为每个任务单独训练 RL 模型；其系统支持百万 token 级 agentic 轨迹，配有可恢复的 microVM 沙箱 [33]。KAT-Coder-V2.5 用 AutoBuilder 把多语言仓库重建为带 fail-to-pass 与 pass-to-pass 验证的沙箱环境 [36]。
- **异步与 partial rollout。** Kimi K3 [33]、Ring 2.6 [34]、Nemotron 3 Ultra [35]、Intern-S2-Preview [37] 都明确采用。Ring 2.6 用二元 KL 散度替代 IcePop 的统一固定比率约束来稳定 agentic RL [34]；Intern-S2-Preview 使用带 off-policy 修正的 partial rollout [37]。
- **RL 之后用多教师在线蒸馏合并专家。** Nemotron 3 Ultra 以异步多教师在线蒸馏从各领域教师获得稠密信号 [35]；KAT-Coder-V2.5 用多教师在线蒸馏统一 SWE、Agent-Claw 与 WebCoding 专家 [36]。
- **面向 harness 的鲁棒化。** KAT-Coder-V2.5 在训练中随机化黑盒 harness，以减少对单一工具协议、上下文格式或控制流的过拟合；同时加固沙箱，减少环境错误造成的奖励污染；并使用非对称 actor–critic PPO [36]。

这些做法的共同点是把“环境、harness、系统”当作与算法同等重要的变量。蚂蚁的 AReaL 2.0 立场文章进一步认为，企业级自进化 agent 的瓶颈主要在在线 agentic RL 系统，而不在 RL 算法 [48]。

## 3. 优化目标与训练稳定性

**算法格局。** GRPO 及其组相对变体仍是主流，但出现了回归价值估计的趋势。SAO 用单 rollout 加价值模型替代组采样 [25]，KAT-Coder-V2.5 使用 actor–critic PPO [36]，Apple 的 LVRL 用冻结 LLM 作免训练的价值函数 [3]。候选中还有大量熵调控方法，例如百度、阿里、亚马逊各自提出的熵调制或不确定性引导探索，本轮未精读。

**崩溃与不稳定的诊断。** 研究地图 Q002 详述了六类单因解释：

- **控制 token 概率尖峰。** 工具调用结构被破坏，底层能力仍在 [8]。
- **周期性熵爆发。** 期间获得的重复与幻觉会累积 [9]。
- **学习率门控。** 中等学习率退化，高学习率崩溃 [10]。
- **有效更新幅度。** Muon 的增益在 RMS 匹配后消失 [11]。
- **harness 侧样本组装。** 重分词、样本拼接、损失归一化处理不当会使训练失效 [12]。
- **时程本身。** 仅时程变长就造成不稳定 [13]。

这些诊断尚未在同一设置下相互比较。

## 4. 信用分配：从“更稠密”到“信息从哪来”

稀疏的终点奖励难以区分长轨迹中各步的贡献，这是近半年方法论文最多的方向之一。代表做法包括：

- **参考模型似然的轮级 TD 信用。** TRACE [2]。
- **冻结 LLM 价值。** LVRL [3]。
- **轨迹图聚合相似状态估计步级优势。** 腾讯 [7]，以及阿里通义的图式信用分配 [49]。
- **针对关键决策的信用。** Microsoft 参与的工作 [50]。

同期出现了几项反思性工作：

- **终态验证器下，信用浓度比定向更重要。** 在只验证终态的 τ²-bench 上，把同等优势分到“进展”轮次与分到随机轮次同样有害，均匀稠密奖励反而更好 [1]。
- **稠密信用有统计风险。** rollout 有限时，侥幸成功的动作会获得过大优势 [4]。
- **结果奖励的“天花板”可能来自探索不足。** 有工作把它归因于探索不足和策略漂移 [5]，该文机构未核实。

一个尚待检验的调和解释是：带来明显增益的方法 [2][3] 引入了验证器之外的新信息，即冻结模型的先验或标准答案似然；而 [1] 检验的是不增加信息、只改变分配几何的情形。见研究地图 Q001。

## 5. 奖励、验证器与 reward hacking

Qwen 团队把编码 agent 的奖励构造分为四类：测试验证器、前端 rubric 验证器、以用户为验证器、长流程自动 agent 验证器。他们认为验证信号的可扩展性、忠实性和鲁棒性难以兼得，验证需要随策略能力共同演化 [14]。

近半年关于 hacking 的证据主要来自受控诱发：

- **多智能体传播。** 在多智能体编码系统中，被诱发的 reward hacking 会经代码、共享记忆和自然语言计划跨角色传播，小模型能诱导更强的闭源目标 [15]。
- **伪工具使用。** 只在 agent 已能可靠使用工具后出现，伪工具调用率最多上升 39% [16]。
- **工具滥用。** 能靠内部推理解决的问题也调用工具，可用难度感知的惩罚缓解 [17]。
- **rubric RL 的 hacking。** 可以通过向 LLM 评审注入偏差来稳定复现 [18]。

工程上，Huawei 的 LEGO-RL 在原生编码 harness 中加入分阶段防护，以应对环境崩溃和 reward hacking 对结果信号的污染 [44]；KAT-Coder-V2.5 加固沙箱以减少奖励污染 [36]。生产级训练中不注入额外信息时的 hacking 发生率，本轮没有读到测量，见研究地图 Q003。

## 6. 环境：从手工基准到可扩展的合成与模拟

环境供给是 agentic RL 规模化的主要瓶颈。近半年各机构的路线大致分四类：

- **从真实资源合成可执行环境。** ByteDance Seed 的 Agent-World 从数千个真实主题中自动探索数据库与可执行工具生态，合成难度可控的可验证任务，并结合多环境 RL 与自动发现能力缺口的自进化竞技场 [38]。Huawei 的 EnvFactory 只用 7 个领域的 85 个已验证环境，生成 2,575 条 SFT 与 RL 轨迹，并强调合成轨迹应包含隐含意图，而不是指令序列 [39]。
- **回放与合成网页。** Apple 的 Weblica 用 HTTP 级缓存回放稳定的视觉状态，并以真实网站为依据做 LLM 环境合成，把视觉网页 agent 的 RL 扩展到数千个环境 [41]。
- **深度而非数量。** Microsoft 的 Echoverse 把规格编译为有状态应用，任务以应用自身数据库评分；环境、任务与验证器随模型共同演化。只在 12 个这样的环境上训练，9B 模型在 14 个评测划分上从 36.5% 提升到 67.1% [42]。
- **语言世界模型作模拟器。** Qwen-AgentWorld 用超过 1000 万条真实环境交互轨迹，训练出 35B-A3B 与 397B-A17B 两个能模拟 7 个领域 agent 环境的语言世界模型 [40]。

模拟带来新的失效模式。用单一冻结 LLM 模拟用户时，模拟器本身的模式坍缩会让策略过拟合到利用该模式的窄策略，迁移到新模拟器和真人时变差。改为口语化采样或与一组可训练模拟器共同训练后，留出集成功率分别最多提升 9% 和 14% [31]。环境的多样性与保真度如何换算成真实部署收益，仍是开放问题。

## 7. 训练系统与 harness

**harnessed agentic RL。** 部署时的 agent 运行在 Claude Code、Codex、OpenClaw 等复杂 harness 里。新框架用代理截获模型调用并记录为训练数据，让 RL 直接在真实 harness 中进行，例如 Microsoft 的 Agent Lightning v1.0 [12] 与 OpenForgeRL [43]，以及 Huawei 的 LEGO-RL [44]。LEGO-RL 还在训练端重新计算对数概率，以在 harness 做压缩或重序列化时保持 token 级对齐 [44]。Agent Lightning v1.0 系统列出了这一范式特有的问题：重分词、样本拼接、优势计算、损失归一化和后端调度 [12]。

**异步与 off-policy 修正。** 长尾多轮 rollout 推动系统走向异步。诊断研究指出了几处语义缺口：

- 实际管线常丢失旧 logits，使训练-推理差异修正与策略陈旧修正纠缠 [23]。
- PPO 裁剪对高陈旧度尾部控制较弱 [24]。
- 组采样不适合异步训练 [25]。
- 轨迹级优势中心化在 token 平均损失下并不居中 [26]。

生产报告普遍采用异步，但本轮读到的段落未披露陈旧度分布，见研究地图 Q005。

## 8. 长上下文与上下文管理

长时程任务会超出上下文窗口，把上下文管理纳入 RL 有两种思路：

- **训练 agent 自己做压缩。** CompactionRL 联合优化任务执行与摘要生成，使用 token 级损失归一化和跨分段的 GAE。在 GLM-4.5-Air 上，SWE-bench Verified 的 Pass@1 达到 66.4%，Terminal-Bench 2.0 达到 26.2% [45]。
- **训练外部管理器服务冻结 agent。** 阿里通义的 AdaCoM 用端到端 RL 训练外部 LLM 管理冻结 agent 的上下文。学到的策略呈现保真度与可靠性的取舍：原本较强的 agent 受益于高保真保留，较弱的 agent 需要更激进的修剪 [46]。

压缩是否破坏策略梯度所需的轨迹一致性，本轮未精读相关实验。

## 9. 特权信息与在线自蒸馏

在线自蒸馏让同一模型在看到参考解或环境反馈后充当教师，为学生提供 token 级稠密监督，2026 年下半年此类论文增长很快。两项工作给出了冷静的结论：

- **统一协议下无方法稳定胜出。** 10 种方法与 GRPO 在 4 个环境、3 种规模、132 次运行、约 1.2 万 H800 GPU 时的比较中，没有方法稳定优于 GRPO；最终性能好可能掩盖训练不稳定；额外成本不一定换来性能 [20]。
- **单独使用时难任务退化。** 自蒸馏作为唯一目标时，在难任务上损失下降而准确率下降，原因是教师目标被拉向特定参考轨迹，损失主要落在低信息 token 上 [19]。

自蒸馏作为 GRPO 辅助项的适用条件仍未定，见研究地图 Q004。

## 10. 评测与增益归因

终点成功率不足以说明 RL 学到了什么：

- **到达与解决。** checkpoint 交接把增益拆为到达与解决两项，五个条件下两者存在正交互 [27]。
- **能力边界。** Pass@(k,T) 显示只有组合式信息收集任务的能力边界被扩展，而匹配数据的 SFT 会缩小边界 [28]。
- **提升空间。** 在已基本掌握的任务上 GRPO 无可信增益，需要采样策略优于贪心策略的提升空间 [10]。
- **SFT 与 RL 分工。** Amazon 的广告 agent 研究把能力分为模仿、提升、发现三种区段，据此决定走 SFT 还是 RL [30]。
- **初始化的影响。** SFT 时同时监督观测 token，在 SFT 后看不出差别，但在 GRPO 后提高 pass@k [32]。

时程方面，固定时程扫描在 AppWorld 与 BFCL 上出现饱和平台，因而有工作提出闭环控制训练时程 [29]。
