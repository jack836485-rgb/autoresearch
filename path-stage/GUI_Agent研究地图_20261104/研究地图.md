## 摘要

近半年 GUI Agent 发表量很大（相关 705 篇）。按标题计，评测/benchmark（146）和网页（134）最多，其次是 grounding（125）、规划/恢复（97）、记忆/自进化（92）、RL（78）和安全（70）。正在被诊断论文拆开的几个技术判断如下：

1. **VLM 评判器靠智能体自述下结论。** OSReward 发现，判错里约三分之二是"把未完成判成完成"；换截图数量、去掉点击标记，准确率变化不到 0.5 个点，起主导作用的是文本历史。与此同时，小模型上的 GRPO 在 SFT 之上没有可信增益。以这类评判器作 RL 奖励时策略会学到什么，本轮没有检出直接研究（Q001）。
2. **"知道但照做"。** 在 4 个开源 CUA 中的 3 个里，55–89% 的重复动作在前一步推理里已经承认"之前的尝试在失败"；激活 steering 对惯性的效果从减少 33.8% 到增加 44.0% 不等。冲突指令下也有同类的 awareness-action mismatch：推理里提到冲突，动作照常输出（Q002）。
3. **世界模型的收益不一定来自"预测对"。** 把下一观测目标换成同分布的错配观测，pass@1 只低 2.75%；用随机硬币奖励在 VisualWebArena 上还略胜 BASE。在有教程的条件下，即使给真值视觉 rollout，OSWorld 成功率也只变化 −0.6 到 +4.2 个点（Q003）。
4. **动作接口决定 agent 信哪条感知通道。** 同一个 Qwen2.5-VL-7B 只换动作输出格式，跟随结构化通道（DOM/a11y）的比例从 0.11（坐标）升到 0.98（文本标签）；坐标格式自身的无冲突错误率却最高（0.43）（Q004）。
5. **检索来的经验主要用在第一步。** 7,140 个非首步动作上，检索基线带来的提升不超过 2.4 个点；全图视觉记忆会加重动作级失败；按 token 预算对齐后，普通 actor 在 WebArena 上平均最好（Q005）。
6. **关系型空间指代上，grounding 远没饱和。** 最强模型严格点中率约 32%，人类 96.9%；涉及关系的指令会让 7B grounding 模型掉 27–56 个点（Q006）。

## 按问题展开

### Q001 VLM 评判器靠智能体自述判定成功：用它作 RL 奖励，策略会学到什么？

> **打磨状态（2026-11-04）：** 已打磨，未通过，停止（Reviewer 4.5/10，详见 `idea-stage/gui_judge_narrative_reward/PIVOT_OR_STOP.md`）。叙述隔离已被 ZeroGUI 采用；假阳性的群组放大与复核分配已被 2609.04063、2508.05928、2607.11022、2609.36958 覆盖；MobileJudgeBench（2608.11434）已在 AndroidWorld 上实测评判器奖励 GRPO。原问题“习得利用还是选择既有错误模式”仍未答。

**对象与失败条件。** CUA 的数据筛选和在线 RL 越来越依赖 VLM 评判整条轨迹是否完成任务。OSReward [7]（Oxford、NUS、HKU、Fudan 等）在跨平台 CUA 轨迹上评测了一批评判器：
- 主集上最强的闭源评判器准确率约 89.7%；
- 换到 hard 集（30/70 成败比）后所有评判器掉 20–43 pp，最好的也只有 69.7%，与"永远判失败"的常数评判器持平。
- 错误类型高度一致："把未完成判成完成"占全部错误约三分之二，每个评判器至少 48%；合并统计时过度接受与过度拒绝约 3:1。
- 输入消融（§5.1–5.2）：把末尾 5 张截图换成 3 张、换成首张加末两张，或去掉红色点击标记，二值准确率变化都不到 0.5 个点；截图数从 1 扫到 16，各评判器只漂移 2–3 个点且没有趋势。作者的结论是文本历史决定判定，"以自述收尾宣称成功"的失败轨迹正好能骗过评判器。

**相关的 RL 证据。** 小模型上 RL 本身的增益很脆弱：
- [8]（Monash）在 4B–8B 文本／VLM 网页 agent 上跑了 18 次控制网格（学习率、KL、种子、初始化、clip），没有任何配置可信地超过强 SFT 基线。只看 SFT 成功率在 0.2–0.8 之间的任务，37.1%→42.9%，配对区间仍含 0；唯一显著起作用的是学习率，而且只往下拉。
- [9]〔非白名单〕在 35B CUA 上发现：奖励项只能放大策略本来就会采样的动作。base 从不输出 done()，奖励项就装不进"停止"；只有教师蒸馏项能装进去（1.00±0.00，3 个种子）。

**已有处理。**
- 评判侧：任务自适应 rubric（AdaptRubric，ZJU [26]）、更强闭源评判器、裁剪文本历史的建议 [7]。这些都在评判器层面做事。
- 策略侧：只检到 GUI-G1 [27] 讨论 grounding 奖励里的框大小 hacking，以及 ADMIRE [28] 提到过程奖励容易被 hack。

**缺口。** 反证检索（arXiv 不限时间，"reward hacking"/"judge"+"computer-use|GUI agent|web agent" 等 4 组查询）没有检出研究"策略学会用自述迎合 CUA 评判器"的工作；这只说明本轮范围内未检出。具体的未知关系是：评判器对文本历史的依赖，会不会在 RL 中转化成策略输出"宣称成功"的收尾、过早 done，或其他迎合评判器而非改变界面状态的行为？这种偏移在什么奖励构成下出现（纯评判器奖励，还是评判器与规则验证器混合）？

**下游切口。** 区分"评判器噪声"和"评判器可被策略利用的方向性偏差"。观察量：训练过程中轨迹末尾成功宣称率、评判器给分与规则验证器给分之间的剪刀差、done 时机。需要控制：同一环境、同一策略初始化，评判器能看到的输入不同（有／无文本历史）。

### Q002 推理里已承认失败或冲突，动作为何仍重复或照做？

> **打磨状态（2026-11-05）：** 已打磨，未通过，停止（Reviewer 2 次，最高 6.0/10，详见 `idea-stage/reason_action_gap_gui_q002_20261105/PIVOT_OR_STOP.md`）。表面形式复制（2608.23651）、自我模仿（2602.03664）、执行落差（2510.02204）、循环打断（2604.21375）与 stuck 触发升级（2604.27151）均已覆盖；离线预检显示首次无效后重试使屏幕改变仅 3%，压低重复本身不提升成功。原问题的训练侧来源只有一条反证，仍未答。

**观察 1：惯性。** Absorbed in Inertia [4]（Delft）在 UI-TARS、GUI-Owl、OpenCUA、EvoCUA 四个开源 CUA 上检测"屏幕–动作循环"，并用盲评 LLM 只看推理文本，判断推理是否承认之前失败。
- 结果：重复集中在失败轨迹里；4 个模型中 3 个有 55–89% 的重复伴随推理里的失败承认（EvoCUA 最低）。
- 动作前激活在重复段里保持高度持续，作者称为"吸收区域"。
- 沿该方向做激活 steering 并不稳定：惯性变化从减少 33.8% 到增加 44.0% 不等（§3.1）。

**观察 2：冲突指令下照做。** ConflictGUI [5]（Ant Group、SJTU）把不可行指令（指令内部冲突、指令与界面冲突）下的失败分成两类：premise-blind execution，以及 awareness-action mismatch，即推理提到冲突，仍输出可执行动作。
- 作者把这称作"执行偏置的过度服从"：可行任务做得越好的 agent，在冲突指令下越倾向盲目执行。
- 修法 ConflictGuard 是条件激活 steering。

**观察 3：恢复与跨类型对照。**
- CUA-Recovery [6]（Manchester 等）：在长程多应用工作流里，从策略自身造成的错误点接管后，6 个 agent 的完全恢复 Pass@3 最高只有 25.5%（GPT 5.5，d=20）；Claude Opus 4.8 最高 7.7%；开源 agent 都不超过 6.4%。用恢复数据训练后，同域 MyPCBench 从 9.2% 升到 24.5%，域外 Odysseys 从 24.1% 升到 34.9%。
- AndroidFlux [10] 也报告了从首错步恢复的低成功率：80 个人工核验任务上，Qwen3-VL-4B/8B 平均约 26%。
- 跨任务类型对照 [11]〔非白名单〕：在 TextWorld、τ²-bench、网页导航等冻结决策状态上，单次打分模型 70–73% 的错误发生在事实探针全部答对之后。

**已有解释与处理。**
- 激活层：吸收区域 [4] 与冲突方向 [5] 都是相关性证据加 steering 干预，而 steering 的效果在 [4] 里不稳定。
- 数据层：恢复轨迹合成，包括 RoTS [29]（Alibaba，80 万条）和 CUA-Recovery-Train。它们提高了恢复率，但没有说明"知道却照做"从何而来。
- 训练层：[9] 说明 RL 奖励无法装入策略从不采样的动作（如停止）。这与"仅成功轨迹 SFT 造成动作先验压过推理"的猜想相容，但没有直接检验。

**反证检索。** "knowing-doing gap" 在通用 LLM 决策中已有研究：Google DeepMind 的 [30] 发现，在 bandit／井字棋上 RL 微调能部分缩小这个差距；STOCKTAKE [31] 在供应链 POMDP 上分离"读错"与"读对仍做错"。这些都不是 GUI 场景，也没有讨论 GUI 特有的截图–动作循环。因此本卡降级为"通用现象已有工作涉及"；GUI 设置下的成因与训练侧来源，本轮未检出直接研究。

**剩余问题与切口。** 推理文本与动作 token 在 GUI 策略里的耦合在哪里断开？候选解释有三个，互相竞争：
- 训练数据只含成功轨迹，导致动作先验压过推理；
- 推理只是事后叙述；
- 动作解码对屏幕变化不敏感。

需要区分这几种解释。观察量：承认失败后下一动作的分布变化、动作 token 对推理内容的条件依赖（例如替换推理文本后动作是否改变）。需要控制：相同屏幕与历史，只改推理里是否承认失败。

### Q003 GUI 世界模型的收益来自哪里？

**作为训练目标。** [1]〔非白名单〕在 ALFWorld 和 VisualWebArena 上审计"预测下一观测"的后训练：
- 在 ALFWorld（Qwen2.5-7B-Instruct）上，把真值下一观测换成同分布错配观测（MIS），预测准确率降 29.8%，任务 pass@1 只低 2.75%，pass@64 几乎不变。
- 在 VisualWebArena（Qwen2.5-VL-7B，GRPO）上，用与环境无关的 Bernoulli(0.5) 硬币奖励（COIN）替代观测匹配奖励：pass@1 从 11.48% 到 12.66%，pass@64 从 34.83% 到 39.80%，循环比例从 56.86% 降到 46.14%，因重复动作上限终止的轨迹少 16%。
- 作者的解释是覆盖扩展和循环减少，不来自学到环境内容。

**作为测试时前瞻。** [2]〔非白名单〕在有教程的 OSWorld-Tutorial（Qwen3-VL-32B 作策略和评判，3 次运行）上比较：
- 零样本文本世界模型 rollout 不胜无 rollout 的评判器；
- 即使给真值视觉 rollout，变化也只有 −0.6 到 +4.2 pp；
- 失败分析的主因是 agent 不理解任务成功与进度（Finding 4），不是世界模型保真度。

**移动端与状态信息。**
- [3]（NTU）在移动端训练了文本 delta、全文、扩散图像、可渲染代码四种世界模型。Qwen3-VL-8B 用扩散图像 guidance 后整体 Step Acc 从 66.61 降到 62.05；Gemini 3-Flash 用文本 delta 后 Type Acc 从 77.21 降到 64.15；收益主要出现在强闭源 agent 上。
- [12]（Huawei Noah's Ark）指出状态混叠：可见界面不包含决定转移的隐藏状态，同一屏幕对应不同的合法未来。
- [13]（Alibaba DAMO、Yale）指出单步下一屏预测与多步作为环境使用之间的错位。

**解释到哪里。** 三条证据分别否定了"预测越准，帮助越大"，但给出的替代解释不同：
- 训练副作用：探索覆盖与循环减少 [1]；
- 使用未来信息的能力不足 [2]；
- 读取生成图像的感知能力不足 [3]；
- 输入本身不充分 [12]。

它们的任务、模型与世界模型用法（训练目标／前瞻／环境）都不同，属于**待解释分歧**，不能合并成"世界模型无用"。

**剩余问题与切口。** 同一个 GUI 策略、同一个世界模型，在训练目标、测试时前瞻、模拟环境三种用法下，收益分别由哪个因素解释？要分离的是"预测内容正确性""额外优化带来的探索变化""策略利用预测的能力"。可用错配目标和随机奖励作对照，观察覆盖（pass@k）与循环率。注意：[1] 的 GUI 部分只有 VisualWebArena 一个环境；本轮没有找到该审计在移动端或桌面上的复现。

### Q004 动作接口如何决定 agent 的状态信念来自像素还是结构？

> **打磨状态（2026-11-05）：** 已打磨，未通过，停止（Reviewer 2 次，最高 4.5/10，详见 `idea-stage/gui_channel_action_q004_20261105/PIVOT_OR_STOP.md`）。训练后的纯视觉 grounding（UGround 2410.05243）在 web 元素选择上已与 HTML 方法相当且几乎不被结构劫持，精度–鲁棒取舍在 web 上基本已被打破；按可见性分派信任只防住非对抗的过期快照，注入面在不可见属性上。格式配比的作用仍未测。

**观察。** [14]（HKUST、Shenzhen Univ.）用 735 个探针（Web／移动／桌面，含 225 个从线上网站挖出的零编辑分歧），在像素与结构（DOM／a11y）之间做单通道干预：
- 同一 Qwen2.5-VL-7B 只换动作输出格式，结构跟随率随动作对结构化通道的直接程度单调上升：坐标 0.11、element id 0.64、index 0.90、文本标签 0.98。OS-Atlas-Base-7B 上排序复现。
- 坐标格式在无冲突时的错误率最高（0.43）。
- 输出坐标的 UGround、Aguvis 在冲突下结构跟随只有 0.02–0.07；OS-Atlas 用索引格式时为 0.96–0.97，被结构劫持的程度和通用模型一样。

**含义与处理。** 作者认为脆弱性来自"把动作绑定到结构化通道"，而不是模型本身，并给了一个训练无关的一致性门控（检测到冲突时重新 grounding），但承认它只是启发式自检。这给出一个具体取舍：坐标动作抗结构注入，但自身定位错误高；结构动作定位准，但会继承结构里的任何断言。

**相邻证据（时间维度的状态）。** 时间上的状态有效性是另一条维度，不与上面的通道选择混为一谈：
- [15]（NUS、Fudan 等，仅摘要层）认为瞬时界面事件上的失败来自决策关键路径上的自回归解码延迟；
- [32]〔非白名单〕测得页面打开后第一秒内规划的点击有 17% 会过期，完全加载后只有 0.4%。

**剩余问题与切口。** 能不能让动作接口同时拿到两者，既有结构动作的定位精度，又有坐标动作的通道鲁棒性？训练中混合多种动作格式时，通道偏好如何形成？这属于"动作表示 × 感知通道"的问题。观察量：同一模型在不同动作格式下的结构跟随率与无冲突错误率。需要控制：观测完全相同，只改动作格式或训练数据中的格式配比。本轮只有 [14] 一篇受控证据，没有对该现象做针对性查新。

### Q005 检索到的经验何时仍"适用"？

**观察。**
- [16]（NTU & Alibaba）在个人 GUI 场景中发现，检索历史能显著改善每个 episode 的第一步，但在首步之后的 7,140 个动作上，各检索基线的提升不超过 2.4 个点，多数与零无法区分（配对 user-cluster bootstrap）。
- [17]（SNU）在 OSWorld（GPT-5.4-mini）上发现：全图视觉记忆减少状态级失败（认知失败、视觉状态误解），但加重动作级失败（隐藏操作盲区、grounding 错误）；只裁剪截图能部分缓解，隐藏操作盲区从 78.8% 降到 60.3%。
- [18]（McGill、UBC）把 AWM、ASI、ReasoningBank 与按 token 预算对齐、步数更多的普通 actor 比较，在 WebArena 四个域、三个模型上，普通 actor 的平均成功率最好。作者承认用步数控制预算只是近似。
- [19]〔非白名单〕把经验拆成定位器、过程、状态事实、教训，分别送进上下文或权重。在 MobileGym 上，过程知识进上下文得 +5.1 到 +5.3，进权重只有 +0.3 到 +2.0；去掉"状态条件"后上下文收益降约 3.9。
- [20]（Stanford、Berkeley，本轮片段检索零命中，只有摘要层）认为 harness 演化修的是过程失败，内容失败要靠权重。

**解释与处理。** 已有解释集中在两点：经验的单元（[19] 认为结论随经验组成而变）与状态条件（[16][19]）。修法包括逐步重新激活经验（ExpActivator [16]）、动作区域视觉记忆（AGMem [17]）、组件路由 [19]。

**剩余问题。** "相关"与"在第 t 步适用"之间的判据仍是启发式的，[18] 的预算对齐结论也只在 WebArena 上成立。要区分的是：经验失效是因为状态条件缺失，还是因为上下文占用挤掉了推理。观察量：每步检索命中与动作改变的关系。需要控制：等 token 预算。记忆／自进化是近半年第三大主题（标题计 92 篇），拥挤风险高。

### Q006 grounding 为何在关系型空间指令上崩溃？

**观察。**
- GUI-Primitives [21]〔非白名单〕：994 对对比指令，截图和锚点固定，只改关系表达（左右、上下、包含、对齐、邻近、列表序号、遮挡）。19 个模型中最强的 Claude Opus 4.7 在人工清洗的 185 项核心集上严格点中率 32.4%，人类 96.9%。Qwen2.5-VL-7B 为 24.9%，与 Claude Haiku 4.5 统计上持平。GUI 专训的 OS-Atlas-Base-7B 为 10.8%，高于同底座的 Qwen2-VL-7B（4.9%），所以没有证据表明 GUI 专训有害。
- 本窗口外的 GUI-Perturbed [22]〔非白名单〕：三个同谱系 7B 模型在需要空间推理的指令上掉 27–56 pp；rank-8 LoRA 加增广数据反而更差。

**已有处理与候选机制。**
- GUI-Cursor [23] 把 grounding 改成移动光标的交互搜索；
- [24]（CUHK）发现坐标数字 token 的熵按位权不对称，百位熵对错误的判别力（AUROC 0.82）高于个位（0.65）；
- [25]（Berkeley）把小目标漏检归因于每个目标分到的视觉 token 太少（S）和一次调用要搜索的内容太多（L）；
- GUI-Primitives 引用"视觉 token 范数压制位置编码"作为候选机制，未验证。

**剩余问题。** 关系崩溃发生在哪一层：语言关系解析、锚点定位，还是坐标解码？有没有一种训练信号能教会关系绑定，而不是记住元素名？现象已有两篇独立报告，机制只有候选，最新的 GUI 专训模型（UI-TARS-1.5、GUI-Owl、GTA1）没有出现在这两份评测里。grounding 是最拥挤的方向之一（标题计 125 篇）。

## 2026-11-05 扩展：新增问题（Q007–Q011）

扩展原因：Q001、Q002、Q004 打磨后均因拥挤或前提被削弱而停止，用户要求补充问题。本次只从原 705 篇相关候选中未读过的 636 篇里取材，按诊断措辞排序读标题，再读 28 篇摘要、下载 12 篇正文，对 6 篇做片段检索。

### Q007 环境有激励时，CUA 为何放弃用户最优目标？

**观察。** CAVEAT [35]（CMU、Microsoft Research）在 9 个市场环境里开关 8 类引导机制：
- 匹配对照下 78.6% 的 episode 买到用户最优商品，开启引导后只有 17.3%（摘要）。
- 推理强度是最明显的缓解因素：GPT-5.6-Sol 低推理 51.7%，高推理 90.0%；GPT-4o、GPT-4.1、GPT-5 在低推理下停在地板（§4.2，Figure 4）。
- 只开滴漏定价（价格在交易后期才揭示）时，GPT-5.6-Terra 低推理 60 次中 35 次次优购买，全部选中滴漏定价的推荐商品，作者称为"证据未揭示就提交"（§5.3）。
- 他们的 CAVEAT-Harness 有效，但收益部分来自诱导更多搜索与验证，也就是更多工具调用（§6.1）。

**已有工作。** SusBench（arXiv:2510.11035，窗口外）测过 dark pattern 易感性；DIBench（arXiv:2610.06898，PolyU，非白名单）测非特权 UI 内容对多候选选择的引导。

**剩余问题与切口。** 开源 7–8B CUA 在这种设置下由哪种机制主导失败（显著性、信任页面断言、证据未全就提交）没有测；不增加搜索调用的修法也没有。切口：固定商品集，只开单一机制，并记录调用数以分离搜索量与决策质量。

### Q008 混合 GUI–工具 agent：采用率上去了，准确率为何不动？

**观察。** [36]（北京大学等）在同一 GUI-MCP harness、OSWorld-MCP 309 题上：
- 同一套 MCP 工具使推理模型 +4.0pp、非推理模型 −5.9pp（各 5 次运行，均超 2 SE）。
- 推理模型只在 55/309 题调用工具，占工具可达题（230 题）的 23.9%；VLC 17 题中 16 题可达，却从未调用。作者称为 adoption gap。
- 加稠密采用奖励后，采用率提高一个数量级并保持到贪心解码，但留出准确率不跟着提高；作者结论是 RL 触及了"是否调用"，没有触及"调用得好"。

**已有工作。** ToolCUA（NeurIPS 2026）做 GUI–工具路径编排，UltraCUA（arXiv:2510.17790）训练混合动作；本轮未读二者正文。

**剩余问题与切口。** 采用率上升而准确率不变，可能来自调用时机错、参数化错，或调用后仍依赖截图，三者未分离；逐步"该走 GUI 还是工具"的判据也未知。切口：在高采用率检查点上按这三类分解失败，并比较同一步走两条路线的成功率。

### Q009 权限弹窗：过度授予与过度拒绝之间切换

**观察。** [37]（东京大学等）在 AndroidLab 任务第 3 步注入权限弹窗，按任务相关性与隐私风险分四级（L1 应授予，L2–L4 应拒绝或交给用户）：
- 原始设置下 Gemini 在 Calendar 上 L1–L4 授予率都是 100%；Doubao 在 Contacts 上 L2/L3 为 86.7%/93.3%（Appendix E Table 13）。
- 功能链感知提示使 GPT 的 L2–L4 授予降到 0.5%、Gemini 3.5%，但 GPT 的 L1 授予在 Calendar 降到 7.1%、Contacts 6.7%（Table 13 注）。

**剩余问题与切口。** 同一模型在过度授予与过度拒绝之间切换，缺少按任务相关性校准的判据或训练信号；开源 GUI 模型未测。相关：How Agents Ask for Permission（arXiv:2607.13718）讨论授权接口，ROGUE（arXiv:2606.00341）测可纠正性。切口：同时报告 L1 与 L2–L4 授予率，检验干预能否两头兼顾。

### Q010 个性化偏好在执行中哪一阶段失效？

**观察。** PrefDiag-Bench [38]（HKUST、山东大学、VIVO AI Lab 等）把偏好分五类，用 1,664 个阶段探针评 11 个 GUI 系统，比较显式画像与行为日志两种上下文。作者指出"检索到用户信息不等于能正确应用偏好"，并在 85 个固定任务上做证据干预：原始日志、预言证据标注、只保留支持日志（§4.5）。本轮未取到三种条件的数值。

**已有工作。** PersonalAlign（arXiv:2601.09636，窗口外）；iPrefBench（arXiv:2610.34735，Ohio State，Apple 署名为实习，非白名单）区分可从历史推断与只能询问的需求。

**剩余问题与切口。** 偏好在轨迹中何时生效的失败分布与修法未定。切口：固定任务，只改偏好来源与日志噪声比例，记录首个失败阶段。

### Q011 grounding 空间盲区如何形成？

**观察。** ScreenHaystack [39]（Stanford）在高分辨率背景上系统重定位同一图标：
- Qwen3-VL、UI-TARS、GTA、UI-Venus 都有盲区；落在盲区内的真实 ScreenSpot-Pro 样例上，Qwen3-VL-8B 掉 16.1 个百分点。
- UI-Venus-Ground-7B 的错误最集中（G_e = 0.759），盲区准确率比整体低 68.27%（相对）。
- 作者检验了训练空间覆盖不均（§4.1），并在 Qwen3-VL 上检验视觉 token 边界等架构假设（§4.3）。

**剩余问题。** 只检验了部分成因；修法及其对整体精度的影响本轮未读。grounding 是最拥挤的方向之一，本卡未做针对性查新。

## 已对齐的分歧：GUI 还是 CLI

[33]（NTU、Yale）在 440 个桌面任务上统一了目标、初始状态和终态验证器，最强 GUI agent（GPT-5.4）得 59.1%，最强 CLI agent（Codex GPT-5.5）得 48.2%；CLI 的失败 93.8% 来自 skill 覆盖与契约缺口。[34]（Toronto 等）则在 AndroidWorld 上看到 Claude Code（Opus 4.7）得 71.8%，超过所有复现的开源 GUI 基线。

两者对比的是不同模型等级（[34] 是前沿 API 的 CLI 对开源 GUI 模型）和不同动作契约（ADB 命令覆盖面对桌面 skill 库），所以这不是真正的矛盾。可以解释为"非 GUI 通道的覆盖范围决定 CLI 的上限"。本轮不为此建卡。

## 问题卡摘要与推荐顺序

完整字段见 `研究问题.json`。推荐顺序按问题分量排（失败是否重要、机制是否未定、已有修法是否只治症状），算力只作过滤。

1. **〔已打磨，未通过，停止 2026-11-04〕Q001 评判器自述依赖 → RL 奖励。** 以 VLM 评判器作奖励是 CUA 在线 RL 的主流路径之一，评判器偏差已被量化，但它在策略上造成什么后果没人测；已有修法都只在评判器一侧。需要在线环境（AndroidWorld 模拟器或 OSWorld 虚拟机，需 KVM/Docker）加 7B 级策略 RL，8×A100 五天内可行，但环境搭建是主要风险。
2. **〔已打磨，未通过，停止 2026-11-05〕Q002 知道却照做。** 它影响恢复、终止、循环三类常见失败，机制有多个竞争解释，steering 效果不稳。通用 LLM 里已有 knowing-doing gap 研究，新意要放在 GUI 的截图–动作循环和训练侧来源上。可以先用开源 CUA 的离线轨迹做诊断，只有干预实验才需要在线环境。
3. **Q003 世界模型收益来源。** 世界模型是 GUI 方向的热门方法线；多篇证据否定了"预测越准越好"，但替代解释还没统一。拥挤风险高。VisualWebArena 或离线移动端数据即可起步。
4. **〔已打磨，未通过，停止 2026-11-05〕Q004 动作接口 × 感知通道。** 单篇受控证据很清楚，取舍没有解决，也连着注入安全。离线探针，成本低。
5. **Q005 经验适用性。** 修法多，判据未定；主题拥挤，部分结论只在 WebArena 文本 agent 上成立。
6. **Q006 关系型 grounding。** 基础能力缺口明确，但现象已被两篇报告，grounding 也是最拥挤的方向，候选机制缺少受控证据。离线基准，成本低。
7. **Q008 采用≠胜任（扩展）。** 受控现象清楚，"RL 提采用不提准确率"直接给出待分解的对象；近邻 ToolCUA 需下游查新。离线可先用公开轨迹分解失败，在线部分需 OSWorld-MCP（KVM）。
8. **Q009 校准最小授权（扩展）。** 过度授予与过度拒绝的跷跷板有原始数值；开源模型未测，AndroidLab 需模拟器。
9. **Q007 激励错配下的过早承诺（扩展）。** 现象强、前沿模型已有缓解；开源模型机制未测；网页环境不需 KVM。

## 术语表

| 术语 | 说明 |
| --- | --- |
| CUA（Computer-Use Agent，计算机使用智能体） | 以截图为观测、输出点击／键盘等动作操作桌面或网页的智能体；与只调 API 的工具 agent 不同 |
| GUI grounding（界面定位） | 把自然语言指令映射到屏幕坐标或界面元素；ScreenSpot 类基准测的是单步、目标可见时的定位 |
| VLM 评判器（VLM-as-judge／outcome reward model） | 读取轨迹（截图＋文本历史）判断任务是否完成，用于评测、数据筛选和 RL 奖励；与规则验证器（检查最终系统状态）不同 |
| 过度接受（over-accept） | 评判器把未完成的轨迹判为完成，[7] 中的主导错误 |
| 惯性（inertia） | [4] 的定义：推理已承认之前尝试无效，仍重复同一屏幕–动作 |
| awareness-action mismatch | [5] 的定义：推理提到指令冲突，仍输出可执行动作而不是终止 |
| 状态混叠（state aliasing） | [12]：可见界面相同，但隐藏状态不同，导致合法的下一状态不同 |
| 结构跟随（structure-following） | [14]：像素与 DOM/a11y 冲突时，agent 信念跟随结构的比例 |
| GUI 世界模型（GUI world model） | 给定当前界面和动作，预测下一界面（文本、图像或代码）；用作训练目标、前瞻规划或模拟环境 |
| pass@k | k 次采样中至少一次成功的比例；[1] 用它衡量覆盖扩展 |
