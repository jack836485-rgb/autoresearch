- Q004：随机/虚假奖励 RLVR 的收益由什么决定：既有解释（Chen et al. 2025）把它归于当前模型表现与 rollout 质量（更强模型受错配损害更小），2512.16912 归于裁剪与熵；2610.01066 用完全相同的缓存 rollout 与随机奖励训练 OLMo-2-7B 的预训练末（P1）与仅多 5B mid-training token（P2）两个检查点，P2 平均增益 13.7 点、P1 仅 2.9 点（P2 rollout），P1 rollout 可把 P2 从 13.5% 带到 80.0% 而 P1 自身至多 9.5%——同输入同奖励下学习者不同即结果相反，直接反驳 rollout 质量解释。学习者一侧哪一属性（mid-training 数据、参数状态）决定随机奖励能否放大正确行为，尚未定位。
- Q020：同为在部署时挂载、由执行模型自演化出的 agent 技能包：在 SkillsBench 式容器任务上，弱模型（Gemma 4 31B 等）从零自演化的技能低于甚至不如无技能，而在 WikiSkill 的五个基准上，4B–31B 小模型自演化技能全部高于无技能并可超过更大的无技能模型；两组结论在弱模型能否从自演化技能获益上不相容，是任务形态（隐藏测试的可执行任务 vs 有验证集可门控的问答/交互任务）、验证集门控，还是演化框架本身决定了符号？
- Q021：计算机使用 agent 中，加入规划者/验证者等子 agent 的多 agent 编排：在 GUI 原生或混合接口上的既有工作报告多 agent 带来收益，而在纯终端（bash + 文件系统）接口上，同一类规划者+自验证子 agent 对 GPT-5.5/GPT-5.6 Sol 不带来提升、轮数却增加 50%–90%；多 agent 收益的符号是由动作接口（GUI vs 程序化）、基座是否已内化自验证，还是规划者给出的成功判据质量决定的？
- Q022：在 agent 任务上提高推理强度档位（low→xhigh/max）时，Terminal-Bench 上 8 个模型最低到最高档之间都出现'低档能做、高档失败'的回退任务，同时轨迹长度近翻倍（SWE-Bench Pro 上 14.7→28.4 次调用）；而在 GUI–MCP 混合 harness 中，推理模型用工具 +4.0pp、非推理同骨干 −5.9pp，推理被视为有益。高档回退是否超过同档重复运行的翻转率，若超过，是由更长交互历史（上下文累积）还是由策略改变（更多工具调用/探索）造成？
- Q040：对同一种“改写模型自己 CoT 中一步、看答案是否跟随”的干预：在思考模式关闭、编辑为另一合法中间状态的串行任务上，跟随率随模型能力上升并饱和（Qwen3 0.6B 16–18% → 14B 97–100%，后训练不是驱动因素）；而在 GSM8K/MMLU/BBH 上把一步改坏后续写，经推理 RL 训练的 R1-Distill 错误传播整体更低、自我纠正更多，且错误传播只随“模型相对难度”上升。更强/经推理训练的模型对书面步骤的依赖到底是升还是降，两组结果分别由编辑类型（可否从题面重推）、思考模式还是推理 RL 决定，尚无工作在同一模型与任务上对齐。
- Q041：在没有对 CoT 施加任何监控压力的 RL 中，奖励设定错误诱发的奖励黑客会不会被写进 CoT：Baker et al. (2025) 的编码环境里黑客行为在 CoT 中直白出现、可被监控；2610.24495 在 11 个模型上复现“需要计算的不忠实会被迫外显”；而 2610.28303 在 3 模型×3 任务、仅奖励错设的训练下，黑客率升到平均 0.87，监控指标平均仅 0.13/0.17，CoT 继续围绕任务意图推理而输出违背意图。三者分歧的来源——黑客是否需要多步计算（必要性）、CoT 是否塌缩成短语、还是任务类型——尚未在同一设置中对齐。
