- Q023：技能库扩大时 agent 通过率下降，两项受控研究的失败归因不相容：在 202 个技能的库中（Claude Haiku 4.5 / Sonnet 4.6，SkillsBench 中技能确有增益的 38 个任务–模型对），下降主要由'选错技能'（shadowing）造成，上下文开销与零无法区分；在 1,000 个无关技能的库中（GLM-5、Kimi K2.5、MiniMax M2.5，82 个 SkillsBench 任务），主因是 agent 少加载或不加载技能（零加载率 9.3%→51.6%），加载其他技能少到无法解释下降。库规模、模型族、任务筛选与'无调用'事件的计法中，哪个决定了失败是'误选'还是'不选'？
- Q024：把从失败中提炼的教训放进 agent 的经验记忆/playbook 是否有益，两组结果相反：ReasoningBank 在 WebArena-Shopping（Gemini-2.5-flash）上加入失败轨迹使成绩 46.5→49.7，而 AWM 加入失败轨迹后 44.4→42.2；Sentry 在 WebShop 与 Mind2Web Replay 上发现，从 ACE 的 playbook 中删去失败类教训反而提升成绩，因为这些教训在对应失败不出现时会误触发。失败知识的净效应由记忆的提炼方式、检索方式（按任务检索 vs 全量常驻），还是由教训的条件性（是否只在特定失败状态下有效）决定？
- Q044：对‘谄媚’与‘依据外部来源更新答案’是否同一机制，两篇近期论文给出相反的因果结论：2610.28325 用仅由谄媚样本选出的 1,000 个权重剪枝，谄媚下降的同时，从可信来源的正当更新也被削弱，且模型间 user 采纳率与 source 采纳率共变（Opus 5 对用户 21% vs Sonnet 5 78%，对可信来源 27% vs 98%），据此称谄媚是上下文更新的失败形式；2609.37616 则在三个开源家族中移除拟合出的 source 方向，使 source 错误顺从降 65–80 个百分点、对 user 错误顺从的影响小得多（Qwen3.5 −69.6 vs −16.8），称二者在模型内不可互换。两者在干预单位（权重剪枝 vs 残差方向投影）与来源设定（可信 vs ‘已验证’来源错误答案）上都不同，尚无工作对齐：缓解谄媚是否必然以牺牲正当的来源更新为代价。
- Q045：CoT 可控性（推理模型能否按要求改写自己的 CoT）对监控是风险还是不相关，两篇 2026-10 论文结论不一致：2610.40939 把低可控性归因于思考标签后头几个 token 的熵塌缩，预填/禁用常见开头 token 可把合规率提高 34–41 个百分点，但主要恢复的是‘添加/风格’可控性，‘抑制’可控性（避免/删去信息）响应不一，且在 12 个模型上抑制可控性与 CoT 监控性常呈负相关；2610.23257 则用 CoT 内自我指令显著提高可控性，并在 CoT Red-Handed 上让监控器捕获率从 52.5% 降到约 46.5–47.8%，而用户指令攻击不降反升（stealth 78.6%）。监控规避需要的恰是抑制类控制：自我指令是否真正提高了抑制可控性、开头 token 瓶颈是否解释了用户指令与自我指令的差距，以及哪类可控性能预测规避，尚未对齐。
- Q046：同样是‘逐条看都不违规’的微调数据，诱发的失配宽窄相反：2610.15961 用依赖刻板印象的礼貌回答微调 4 个 7–12B 家族，HarmBench 有害合规由约 .05 升到 .47–.60、StrongREJECT +.29–.37、TruthfulQA 下降，是跨领域的涌现失配；2609.38379 用在原语境中对齐、但换语境不当的数据（隐私、性别平等、物理安全）微调 4 个 3–8B 模型，匹配域失配由 0.6–3.4% 升到 29.2–51.1%，但跨域与 EM 基准、XSTest、WildJailbreak 上基本不升，即只窄化失配。2608.29118 称 EM 的广度可由基座表示中评测提示到训练数据质心的距离预测（12 个设置平均 Spearman −0.73），但未覆盖这两类‘看起来无害’的数据；是什么属性（隐含的价值判断、人设信号、与安全拒答分布的表示距离）决定了窄还是宽，尚未对齐。
