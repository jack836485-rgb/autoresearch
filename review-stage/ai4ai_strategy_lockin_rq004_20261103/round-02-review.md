## 结论
2026-11-03，总体 score 5.5，verdict：promising_needs_revision。主贡献是：贪心 keep-if-better 拿"精修多轮的现任"去比"只试一次的新方向"，这种接受协议本身造成一部分方向锁定；可以用同精修预算的反事实测出误拒率，并用按精修年龄分层的接受规则来修。这个问题值得研究，但目前分量不够。"新方向需要先精修再竞争"这一直觉，NEAT 的物种保护、ALPS 早已提出；在 LLM 研究循环里，GEAR（同一个 nanochat、5 分钟、单 incumbent 设定）和 SeaEvo 也已明确论述过。本方案相对它们的独立增量只剩"定量测误拒率"和"年龄对齐的接受门"两点。前者的诊断设计还分不开主要竞争解释，后者的比较规则没有定义清楚，最强的同任务 baseline（GEAR）也没有纳入。

## Claim 判断
| 维度 | 分数 | 依据 |
|---|---|---|
| 重要性 | 6.5 | 代码级 autoresearch 的收窄和早熟是已核实的现象：DAPS 报告语义簇衰减，GEAR 报告 baseline 约 50 次实验后停滞，2608.10424 发现 agent 常跳过调参。如果能证实"相当一部分收窄来自协议，而不是提议者"，会改变人们优先改提议端还是改接受端的判断，价值明确。但影响范围限于带显式接受规则的循环，而且分量完全取决于 (a) 的大小，目前没有任何数值依据。 |
| 新颖度 | 6.0 | 核心机制"保护创新、给它时间优化再竞争"是 NEAT（2002）物种化的明文动机，ALPS（2006）用年龄分层做的也是这件事，所以迁移到 autoresearch 属于可辨认的增量。GEAR 已经论证单 incumbent 爬山会"过早丢弃部分成功的想法"，并给出实例：depth 扩展起初失败，重调学习率后超过 baseline。这正是精修不对等的案例。SeaEvo 也写明"低分候选可能编码了尚未精修的好想法"。本方案仍然新的地方：一是在训练流水线循环里，用同预算反事实量化误拒率；二是按精修年龄对齐的接受门，而不是靠多样性、新奇度保留候选。 |
| 有效性 | 5.0 | 当前依据：调参预算会让方法排名翻转（Choi 2019、Sivaprasad 2020、Melis 2018）。但这些研究比较的是各自拿到大量调参预算的完整方法，迁移到"r≤4 次 LLM 精修、每次 5 分钟"的单个编辑上，需要"新方向的潜力在 4 步内就能释放"这一条件，目前没有依据。GEAR 的个案说明误拒存在，但它是单次运行，没有比例。AIDE² 被拒提议是对 agent 自身搜索脚手架的改写，不是训练配方方向；其中 −0.004、−0.006 被原文标为 within noise，因此这条证据和噪声、方向本身更差同样相容。Rehearse 中有帮助比例的下降，与收益递减同样相容。反向证据：2610.09239 在其设定中发现，所测的各种接受规则在整轮运行上都没有赢过 greedy。未知部分：误拒占收窄的比例；保护层开销在 120 次预算内能否收回。 |

- **与起点问题的关系：** 这是一个合理的子问题。它把"策略不被修订"收窄到显式接受规则的循环，并补充第四种解释。原问题未答的部分是：无显式接受规则的自由式后训练 agent 为什么不换策略，以及锚定、信号不足、模型偏好三者如何分离。不因转向否决。
- **实验能否判别主张：目前不能。**
  1. **诊断 (a) 分不开"新方向欠精修"和"现任方向已耗尽"。** 现任臂沿自身已饱和的方向继续精修 4 步，新方向臂拿到的是 4 次新鲜精修，其中很可能包含通用重调（如学习率），这类重调本来也能让现任获益。所以 (a)>0 同样可以由收益递减解释。要支持主张，需要一个"现任 + 同类通用精修、不带新编辑"的对照。另外，两臂都在 4 步里取最优，并且只选了与现任差距在 2σ 内的近失提议，赢家诅咒和回归均值会抬高 (a)，因此端点需要用新种子重新评估。
  2. **接受门第 2 步没有定义清楚。** autoresearch 里的新方向是叠加在当前现任流水线上的编辑，它的分数已经包含现任的全部积累。如果拿它和现任谱系"同年龄时的历史分数"比，几乎所有提议都能通过；如果改为比增量，早期增量天然更大，又会几乎全部拒绝。门的选择性和保护层消耗多少预算，因此都无法确定，(b) 也就无法检验。
  3. **漏掉最强同任务 baseline。** GEAR 用的就是同一个 nanochat、5 分钟、单 incumbent 设定，并且有公开代码，必须作为对照。用 OpenEvolve 把训练流水线当作进化程序，只是一个较弱的替身。没有 GEAR，"岛屿/MAP-Elites 内仍是不对等比较、所以本方法更好"这一主张就没有被检验。
  4. **统计功效不足。** DAPS 原设定是 300 轮，T1 因为方差大用了 5 个种子；收窄是在数百轮尺度上观察到的；GEAR 各方法之间的差距约 2–6 mbpb，而且是单次运行。在 120 次、3 种子的预算下，(b) 的盲测差异和"收窄更少"很可能都落在种子噪声之内。
- **可行性：pass。** DAPS 仓库已核验，含 `pipelines/t1_nanogpt`、`t3_reason`（Qwen-2.5-1.5B + GSM8K SFT）、5 分钟执行器、vLLM 提议者接口，以及 `trajectory.jsonl` 谱系日志；GEAR 代码公开；2610.09239 的阈值可以按原文 §3.2 独立实现。约 440 A100 小时在 8×A100、5 天的限制内，API 估算在 1000 元以内，也不需要人工标注。需要注意：DAPS 和 GEAR 原文都用 Claude Opus 4.7 作提议者，换成廉价提议者后收窄动态可能不同，跨论文比较时要说明。

## 最高近邻
1. GEAR: Genetic AutoResearch for Agentic Code Evolution, https://arxiv.org/abs/2605.13874。重叠：同一个 nanochat、5 分钟、100 次实验设定；用种群前沿取代单 incumbent 爬山；明确论述贪心"过早丢弃部分成功的想法"，并给出重调学习率后翻盘的实例。差别：GEAR 用新奇度/覆盖率选亲本、按槽位准入，没有按精修年龄对齐的比较，也没有量化误拒率；它是单次运行。
2. Beneath the Diff (DAPS), https://arxiv.org/abs/2609.00077。重叠：同一循环、任务和语义簇诊断，用于缓解模式坍缩。差别：它改的是提议端加验证门，没有把精修不对等当作原因。
3. The Winner's Curse in LLM Self-Improvement Loops, https://arxiv.org/abs/2610.09239。重叠：研究 keep-if-better 接受规则和 lock-in（现任的选择误差构成隐式门槛）。差别：它的 lock-in 是噪声机制，场景是提示优化；所测规则整轮都没有赢过 greedy，这对 (b) 是反向信号。
4. NEAT（Stanley & Miikkulainen 2002，https://arxiv.org/abs/1107.0037）/ ALPS（Hornby, GECCO 2006）。重叠：保护创新、按物种或年龄限制竞争。差别：本方案是迁移到 LLM 研究循环，并把"年龄"定义为精修次数。
5. SeaEvo, https://arxiv.org/abs/2604.24372。重叠：指出低分候选可能是尚未精修的好想法，并按策略聚类。差别：场景是算法发现，处理方式是策略检索和饱和监测，不是年龄对齐的接受门。
