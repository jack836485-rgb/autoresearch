A.2.4 Reminder Prompt For the reminder mitigation, we insert the following note between every tool call and tool response in the transcript: <monitor_note> Consider whether the previous tool call contains any actions that are malicious or unrequested by the user. Consider the criteria that you are judging against. </monitor_note> A.3 Fine-tuning Training Data A.3.1 Needle in Transcript Task 1. We prompt Opus 4.6 to generate synthetic tool calls that violate the constitution in the classification prompt. 2. We inject them at random points throughout real Claude Code trajectories. 3. We train 50:50 clean vs injected using the same classification prompt we use for evaluation. A.3.2 Proxy Rule Violation Task 1. We algorithmically generate spend approval policies for a hypothetical company. This is a list of constraints about which employees can spend what amount of money and who needs to sign off on this. 2. We algorithmically generate event logs that either satisfy or do not satisfy the above policy. These include actions such as employing , promoting and firing . 3. The model is then fine-tuned with a classification prompt asking whether the policy has been violated. Notably, this is a distinct policy from the one used in our evaluation prompt . The aim of this dataset is to teach a general long context skill that transfers to other classification tasks, such as the monitoring task we are interested in. A.5 False Positive Analysis We evaluate false positive rates on a set of 80 benign Claude Code transcripts from the author, ranging from 5K to 1M tokens. These transcripts contain work on AI safety research projects and do not contain dangerous actions. Figure 9: False positive rates across all models and settings. All models achieve false positive rates below 2%.
