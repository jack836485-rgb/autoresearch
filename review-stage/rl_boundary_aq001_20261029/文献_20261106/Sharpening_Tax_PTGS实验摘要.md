# Sharpening Tax（arXiv 2610.01509）PTGS 实验摘要

读取日期：2026-11-06；来源：arXiv HTML 版（原文 HTML 与抽取文本在本目录）。

## 设置（§5 与附录 A.5）

- 起点：Qwen2.5-7B-Instruct，RAGEN 框架。
- 环境：Sokoban（单箱，塑形奖励）、FrozenLake（滑冰版，二值奖励）。每局最多 5 轮，每轮最多 2 个动作。
- 训练：PPO 与 GRPO，各有无 PTGS；200 步，每步 8 个任务 × 16 条轨迹；无 KL 惩罚；5 个种子。GRPO 取验证成功率最高的检查点，PPO 取最后一个。
- 评测：64 个离线任务，每任务 128 条轨迹；指标 pass@1、pass@128、Tax(128)。

## 表 5 结果（%）

| 环境 | 模型 | pass@1 | pass@128 | Tax(128) |
|---|---|---|---|---|
| Sokoban | 起点 | 20.7 | 76.6 | – |
| | PPO | 46.5 | 55.0 | 0.094 |
| | PPO + PTGS | 61.1 | 69.7 | 0.081 |
| | GRPO | 36.5 | 55.3 | 0.081 |
| | GRPO + PTGS | 39.1 | 72.5 | 0.025 |
| FrozenLake | 起点 | 26.3 | 89.1 | – |
| | PPO | 63.7 | 74.1 | 0.039 |
| | PPO + PTGS | 65.0 | 80.0 | 0.020 |
| | GRPO | 63.4 | 77.8 | 0.029 |
| | GRPO + PTGS | 67.3 | 81.2 | 0.028 |

原文结论：针对具体任务做 RL 仍然存在“准确率与覆盖”的矛盾，两种算法都在提高 pass@1 的同时丢了覆盖；PTGS 同时提高 pass@1 和 pass@128、降低锐化税。

## 附录 F.3 案例

“起点在 128 次里至少解出一次、RL 训练后一次也解不出”的任务，PTGS 能找回约一半。两个案例（sokoban_25、frozen_lake_43）里，起点的成功都来自**开头那一步的规划**（例如先向右绕到箱子另一侧再推），PPO 丢掉的正是这种开头。

## 对 A-Q001 的影响

1. 前提“纯 RL 在多轮任务上会丢覆盖”已有直接证据（短程小游戏，最多 5 轮），之前“不确定是否存在”的说法不对。
2. 新意只能落在：较深的真实多轮任务（WebShop）上的**逐轮定位**，以及**推理期对应物预测训练增益**（主贡献，仍未见先例）。
3. 风险：若 WebShop 上覆盖也只丢在第 1 轮，“多轮与单轮不同”的卖点不成立。
4. PTGS 必须作为基线加回实验设计。
