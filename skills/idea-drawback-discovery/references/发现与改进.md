# 文献驱动的发现与目标演化

## 优先复用文献，而不是重跑领域综述

从输入Map提取证据、当前解释、近邻和已缓解边界；在线读取相关方法、实验和附录，保留链接／版本／位置，不缓存原文或下载仓库。补查只服务于缺失机制、迁移启发、重合或复现入口。尚未成形的方向与放弃理由通过discovery-note追加到json/REVIEW_STATE.json的discovery_notes，不写进人类候选文档，不另建笔记文件。

Map 内列出的最高近邻是起点，不是最终排他名单。发现重叠更高的作品时，在候选里说明机制差异，保留初始来源而不改写它。查新不限年份、机构白名单；调查用的样本边界不等于全学术领域。

## Route 1：成熟机制迁移

先写出当前不足的输入、输出、核心变换、成立条件和失效。再问哪些其他领域具有相同结构，而非先找一个想拼进去的算法名。读取成熟机制的原文与实际验证，映射：共享结构、必须调整的表示／假设、不能迁移的部分、调整后仍可测试的效果。

例如图像扩散迁到离散语言，值得分析的是“扰动状态逐步恢复”的结构；离散状态、扰动和反向转移必须重新设计。这个历史例子只说明推理方法，不是当前可申报新意。引用它时可直接追 [DDPM](https://arxiv.org/abs/2006.11239) 和 [D3PM](https://arxiv.org/abs/2107.03006)，不能宣称逐步去噪迁移仍未被研究。

对于 Agent 记忆，数据库版本维护、事件溯源或信息瓶颈可能提供机制启发，但须确认其假设是否适合不完整、自然语言、会漂移的状态；不能仅写“memory + database”。没有成立条件映射的迁移要放弃。

Story line：具体失败及证据 → 已成熟的类似机制 → 共同成立结构 → 最小必要适配 → 相同核心预算下可支持或推翻的预期效果。

## Route 2：最高近邻的不足

优先用已有近邻，读懂输入、关键操作、监督／目标和输出；沿 `方法机制 → 核心假设 → 失效条件 → 领域级 drawback → 新机制` 追问。一个模块好改不表示该模块就是研究对象。

RLHF/PPO 到 DPO 的有效推理并非“换一个 loss”，而是从偏好、显式奖励建模及策略更新的关系出发，推导可直接从偏好构造的目标。这是机制级推理示例，已有 [DPO](https://arxiv.org/abs/2305.18290) 本身不是新候选。对当前邻居也应说清机制改变了什么关系／假设，而非用模块名称充当理由。

最小实验同时能检验原有不足是否存在，以及新机制是否改变该不足。在已有明确诊断时可以复用其证据和协议，不为凑流程重复无争议实验。所有未运行结果写为假设／成功和推翻条件。

移除近邻论文名称后，候选仍须能说明独立问题、Claim、实际机制与可检验差异。仅补缺失模块、补实验、换数据集或完成近邻项目的方案标 `baseline_patch`，记录但不选；代码上很小的改变也可有机制级新意，不能按代码行数判断。

## Route 3：未覆盖的任务

两条高优先级路线都实际尝试后，当前无 `available` 且自评分 > 7 的 Route 1／2 候选时才能进入。被审查覆盖／否决的旧候选不算当前合格；需要先尝试前两路线的实质改进，再判断后备条件。目标演化不重置已完成的有效审查或Brain追加的预算；每个目标Problem至少十轮。

从真实不足沿任务阶段、对象、约束与状态细分，找到现有任务测不到的反复问题。记录可访问案例／数据、为何已有指标测不到、输入、输出、可生成或取得的数据和评价量。RAG 图记忆维护可将图及新增交互作为输入、节点／边更新作为输出，评价后续检索、结构和维护成本；“manager”名称本身不产生新任务价值。

若无真实任务证据或不能定义输入／输出／评价，就不生成合格候选。若 Route 1／2 新增合格候选，停止继续开拓 Route 3；已登记的合法 Route 3 候选仍留池比较，最高分原则不变。

## 多不足比较与目标演化

Slot 是完整循环，不是必须解决所有输入不足的任务清单。保留初始 `problems`、`drawbacks`、`pre_solution_idea` 和约束原样；后来证据与候选可以聚焦、合并或发现新的相关不足。新 drawback 用稳定 ID，并注明关联初始问题、证据与新旧关系，不把它偷偷插入初始集合。

每版完整候选在json中记录以下字段；人类Markdown只展示实际预计处理的不足全文及背景、Claim、方法、最小实验、Storyline：

- `initial_drawback_ids`：从哪几个初始不足出发，可以少于初始集合。
- `addressed_drawback_ids`：当前方法预计处理并为之设计验证的不足；不表示已解决。
- `newly_identified_drawbacks`：本版新发现的相关不足及证据；无则为空。
- `goal_difference`、`goal_evidence`：相对原始范围的变化及支持它的原文／观察。
- `constraints_alignment`：仍关联初始范围，符合哪些硬约束；存在冲突时据实说明并阻止选择。
- `pre_solution_idea_used` 及说明：是否沿用初始假设的实质机制，而非只沿用问题名称。

例如初始目标为“压缩后出处丢失＋跨任务经验迁移”，候选可能发现最小可检验机制只处理出处绑定，经验迁移需不同监督；有证据时可缩小范围并将迁移列为未覆盖，不算违规。如果用户硬约束要求两项都处理，则不能悄悄缩小。扩大到相关的更新时间冲突需真实证据；转去完全无关图像任务不合格。

`pre_solution_idea` 只作为普通研究假设。具体时按同样轻量查新、自评分和可行性标准登记 `route=pre_solution`；它没有 Route 1／2 的优先权，也不免除基线或独立贡献要求。其他候选高分就先审其他候选。最终 `pre_solution_idea_used=false` 完全有效。

## 候选资格与 Improvement

预算未满时，自评分低或暂时无available者不允许研究早停。先检索并形成实质新版本；无合格者可对最高分待改进候选作探索性审查，诚实保留低分、已有重合及复现缺口。已覆盖或纯补丁不反复送审凑数。每轮有效审查必须对应不同实质候选/版本，继承历史不继承过关资格。提前通过保留该分支，继续其他分支；预算将满先向Brain报告是否存在值得追加的具体机制缺口。

形成多个实质不同方案，再分别做轻量查新。自评分是一个总体判断，依据问题价值、机制独立性、可验证性、目标演化证据和可行性；不把五个因素机械加权。无法查清的重合降低信心，标明需要 Reviewer 进一步检索。

实验 baseline 需要同领域、同任务和同评测设置，不能用跨域启发方法作实验对照。非平凡方法需亲自打开对应官方／作者仓库，核实实现、权重／数据、入口和配置；仓库提到方法名不算复现证据。简单标准基线可无仓库，但需完整可本地实现的定义，无不可取得依赖。不可复现的最高近邻仍参与创新边界判断；若关键区分只靠无法比较的结果，实验可验证性未成立。

Reviewer 失败后先读最高近邻原作，区分已覆盖、假设错误、目标演化依据不足与实验不可判别，再改 Claim、机制或目标。真正改动新建候选，父 ID 指向旧版，保留旧评分与审查；只堆组件不算改进。可重新选择以前未审的高分候选，不能自动继续上一版。

Reviewer 通过后，完整写作只能解释通过的核心机制与目标，不悄悄扩大 Claim。发生实质变化必须重审，仍须完成同Slot各Problem当前预算，Brain可依据潜力追加。
