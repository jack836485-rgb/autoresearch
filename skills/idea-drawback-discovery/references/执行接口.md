# 输入、最少产物与状态工具

Slot承载完整Loop，接收相关Problems、多不足和可选假设；初始来源只读保存在 `RAW_IDEA.md`，后续变化写候选，不要求全部覆盖软目标。

输入保留 `slot_path, problem_id, problems, drawbacks, pre_solution_idea, problem_map_context, constraints`，增加可选review_problem_ids指定目标Problem（默认全部初始Problem）。每个目标初始review_budget为10；预算单独存状态，Brain追加不改初始输入。Problems条目含ID与内容；drawbacks含ID、描述、来源Problem和证据；可接受字符串不足并初始化稳定ID。约束分hard/preferences，Map上下文保留原文URL、版本和边界。

## 文件契约

Slot根目录只允许 `RAW_IDEA.md`、`IDEA_CANDIDATES.md`、`CURRENT_IDEA.md`、通过后的 `FINAL IDEA.md`／`EXPERIMENT_HANDOFF.md`、实际各轮 `round-NN-brief.md`、失败可选 `PIVOT_OR_STOP.md`。

原始审查另保留 `reviews/round-NN-review.md`，每轮一份，不另写终审汇总。实际提示保存为 `prompt/improve-NN-prompt.md` 和 `prompt/round-NN-review-prompt.md`；前者由总控在调用前保存，后者由prepare-review保存。独立执行时保存实际收到的Improver任务文本。只记录实际完整提示，不附加评分、摘要或后来改写的指令；恢复及实质追加指令另用新improve序号。历史提示无法恢复时据实说明，不用当前模板替代。

所有机器文件在json：输入、状态、结果和同轮prompt／解析；临时候选／回复JSON也放这里，记录后无需重复保留。不生成资料、代码、缓存或额外发现／流程报告。

`IDEA_CANDIDATES.md` 是精简的人类视图：每个候选有ID及标题，正文只含处理的不足、背景、核心 Claim、方法、最小实验、Storyline。处理的不足从初始drawbacks及全部候选登记的新不足中按addressed_drawback_ids查出完整描述；多个不足逐条展示，不只放编号。缺少描述应修正JSON记录，不以编号代替内容。这里的处理仍表示方案拟解决并设计验证，不代表实测成功。

完整候选、评分、选择、路线、父子关系、查新／复现依据、目标演化和Review历史保存在 `json/REVIEW_STATE.json`，不从精简Markdown读取执行信息。尚未成形的发现及放弃理由通过discovery-note追加到同一状态的discovery_notes数组；候选文件由工具生成，不手工插入内部字段或发现段。原始论文和代码在线阅读，记录链接及关键依据，不下载整库或生成实验代码。

## 命令

使用skill内的 `scripts/slot_state.py`，不在Slot生成脚本。输入与候选文件以UTF-8写入json，Brief可直接写 `CURRENT_IDEA.md`：

```text
python -X utf8 <skill>/scripts/slot_state.py init --input <slot>/json/SLOT_INPUT.json
python -X utf8 <skill>/scripts/slot_state.py route-attempt --slot <slot> --route route1 --reason "机制映射和原文依据"
python -X utf8 <skill>/scripts/slot_state.py assess-pre-solution --slot <slot> --reason "独立判断，不给来源加分"
python -X utf8 <skill>/scripts/slot_state.py discovery-note --slot <slot> --reason "未成熟方向、原文依据及放弃或继续理由"
python -X utf8 <skill>/scripts/slot_state.py register --slot <slot> --candidate-file <slot>/json/候选-001.json
python -X utf8 <skill>/scripts/slot_state.py prepare-review --slot <slot> --candidate-id IDEA-001 --brief-file <slot>/CURRENT_IDEA.md --reason "未完成预算问题的最高候选；无合格者时探索性审查"
```

prepare保存根目录各轮Brief，将完整提示原样写入 `prompt/round-NN-review-prompt.md`，并在 `json/round-NN-review.json` 保存prompt及prompt_path，不计调用数；返回字段 `prompt` 是应嵌入新Reviewer的完整允许文本。调用时直接使用该文本，不追加候选池、自评分或历史。不能将整个机器记录、prompt目录或路径传给Reviewer，因为它们包含其他调用及内部元数据。

紧邻真实spawn前start；实际返回的新ID绑定，失败或格式错误记真实调用，但不计有效完成轮次。回复通过JSON字段 `raw_response` 传入，由record统一生成reviews中的原回复Markdown，调用方不再另存重复回复：

```text
python -X utf8 <skill>/scripts/slot_state.py start-review --slot <slot>
python -X utf8 <skill>/scripts/slot_state.py bind-reviewer --slot <slot> --agent-id <实际新ID>
python -X utf8 <skill>/scripts/slot_state.py record-review --slot <slot> --response-file <slot>/json/回复-01.json
```

record将原回复、解析结果和调用标识合并到同轮机器记录，更新候选历史。工具错误用 `--error`；只有尚未start的prepare可discard。真实次数、失败、阈值和全新Reviewer规则不因文件精简改变。

未过后亲读原作并新增实质候选；旧内容／评分不覆盖，classify只记录状态及理由。恢复读取RAW与json状态，不清零次数；提前通过保留旧版本，新实质改进登记父子版本并重审；另选分支不能抹去已通过候选。未知参数待确认。

## 结束与返回

`finish`和研究`stop`先核实每个目标Problem已完成当前review_budget（初始各10轮，含Brain追加）；不足拒绝结束。提前通过可继续登记候选。真实输入/工具阻断保存未完成状态与历史，可恢复；不得用阻断状态包装低分早停。`finish`再核实已通过候选与非空最终文档。都只写 `json/SLOT_RESULT.json`，不生成终审报告。字段保持上游协议：

`problem_id, slot_path, status, best_candidate_id, reviewer_score, verdict, final_idea_path, candidate_pool_path, experiment_handoff_path, blockers, initial_drawbacks, addressed_drawbacks, unresolved_drawbacks, newly_identified_drawbacks, goal_evolution_summary, pre_solution_idea_used`，以及minimum_reviews_per_problem、review_budget、problem_review_counts、review_budget_complete和reviewer_calls_used。

状态仍为experiment_ready、blocked_max_rounds、no_viable_candidate、blocked_input、blocked_review_unavailable、blocked_finalization。失败final/handoff路径null；无审查评分null，不挪用他人分数。addressed是当前方案声称处理且设计验证的目标，未实测解决。新不足含证据及problem_ids关联初始问题，ID不覆盖初始集合。

JSON是程序交换／恢复记录；人类只读指定Idea文档。结束时向总控返回同一结果对象，不另生成可读摘要。
