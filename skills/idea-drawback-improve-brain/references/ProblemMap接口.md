# 输入与 Problem Map 映射

接受用户给出的 `path-stage`／`path_stage` 路径：指向 `研究问题.json`、带该文件的具体调研目录，或中文研究地图。顶层 `path-stage` 有多个领域／历史版本且无法唯一区分时，询问具体范围，同时可读取相关候选目录；不要混合无关地图或自行写一篇新 Landscape。

## 当前实际结构

`ai-research-landscape` 的问题卡根对象含 `领域`、`检索日期`、`近期窗口`、`机构口径`、`研究问题`。卡片含 `id`、`具体问题`、`证据`、`已有解决方法`、`已支持的解释`、`待验证解释`、`尚未解决`、`可检验切口`、`已知边界`、`解决状态`、`查新状态`、`与其他问题的关系`。

每份证据保存论文 ID、标题、机构、原文 URL、实际阅读版本、位置、实验设置、变量、对照、观察、成本和边界。主文 `研究地图.md` 用同一 Q ID，文献笔记／原文可能只读复用其他历史 slot。保留这些路径和来源，不复制所有大文件，也不改 Map。

此结构**没有强制的 `drawbacks` 或“最高近邻”字段**。需要总控根据当前尚存的具体不足提取稳定标识，区分已有解决、作者假设、失败观察及未测试范围；不能靠字段名或标点自动拆出所有开放问题。诊断论文也不自动是机制重合最高的近邻。若已有 Map 明确给出近邻，优先复用；否则说明暂定近邻／待下游核实，不猜一个排名。

## 规范化规则

| 原内容 | 交给下游的内容 |
| --- | --- |
| 卡片 `id`、`具体问题` | `problems[{problem_id, problem}]`；保留整卡作为 `problem_map_context.problem_records` |
| 有证据的具体失败、`尚未解决` 的仍有效部分 | `drawbacks[{id, description, problem_ids, evidence}]`，例如 `Q002-D01`；保留来源 ID 和原文位置 |
| `证据` | 原结构不丢字段地放入文献／limitation 上下文，数值绑定原版本 |
| 已有解法、已支持／待验证解释、边界、查新状态 | `problem_map_context.background`；不压成“全领域无人解决” |
| 明确或暂定机制近邻 | `closest_neighbors`，给原文、重叠机制及已知边界；暂定状态写明 |
| 原地图文件与资料位置 | Group 来源链及下游只读来源，不授权写这些位置 |

初始不足 ID 在整个 Group 内稳定，联合 Slot 可用同一 ID；不同候选的新不足 ID 在其 Slot 内使用 `(slot_id, drawback_id)` 命名关系，不把两个 N001 自动合并。新旧问题的关系与证据分别保留。

若输入仅 Markdown，总控直接阅读并在规划的 `problems` 提供规范化记录、来源路径／位置和证据。状态工具仅接收这份人工提取；它不伪装成 NLP 提取器。已有规范化 `problems` JSON 也可按其实际结构读入。

## 用户筛选与约束

用户指定的 IDs／问题内容优先；限定问题时，关联的其他问题只能作为背景或用户范围内的联合目标，不能自动扩大硬范围。没有指定问题时，按当前研究目标、具体证据价值、剩余技术状态和可验证性选择，不按负面词数量评分，也不要求九张卡都产出 Idea。

`constraints` 推荐分为 `hard` 与 `preferences`，包括研究域、必须／禁用方法、资源／数据、时间及排除项。初始多个 drawback 不默认是必须全部解决；用户明确全部覆盖才写硬约束。各 Slot 必须继承用户全部硬约束，额外限定只能是与用户约束一致的研究边界，不能 silently 删除限制。未知核心实验参数留给下游交接确认。

Map 的日期和机构筛选是调研来源范围，不是下游创新性查新范围。总控只补查足以规划的缺项；进一步方法迁移、机制查新和基线复现由下游执行器完成。
