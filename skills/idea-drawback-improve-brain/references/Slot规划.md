# Multi-Drawback First 的 Slot 规划

一个 Slot 是独立研究方向和完整循环，不能简单等于一个 Q ID、一条 drawback 或一个方法名。先分析不足之间的关系，再定方向；不创建“每个不足一个 slot”的默认笛卡尔展开。

## 联合是否自然

共同原因为原文已支持还是仅假设？两个失败是否沿同一因果链出现，是否共享信息不足、状态不可辨认、监督错位等机制瓶颈？它们的输入输出和必要干预是否相容？一个最小机制能否同时改变两项可测量结果？沿这些问题形成直接判断，不建评分表或机械阈值。

可以联合的例子：摘要后丢失事实出处和更新后事实缺乏时间有效性，都可能涉及事实—来源—版本关系的保留。若有证据支持共同表示缺口，可规划一个研究方向验证统一关系维护；不要把“版本关系是已确认根因”写成定论。

应拆开的例子：摘要出处丢失与 GPU 回收导致高并发尾延迟，虽然都出现在 Agent 系统，直接作用的对象、测量和干预不同。除非已有具体桥接机制，否则同 slot 强行组合通常导致两个独立子项目。具有相反资源条件的不足也可能冲突；联合会使最小实验不可判别时拆分。

同一组不足可有不同 Slot，例如保留显式关系与学习压缩表征两种独立假设。但 `exploration_goal` 要围绕可验证关系，方法只是 `pre_solution_idea` 中可放弃的启发；若用户本身固定方法，则放硬约束。每个重复目标方向说明独立假设／机制或验证条件的实质差别，不把换标题／角色提示当新 Loop。

每组关系在规划中保留源 drawback ID、关系类型、原证据、共同机制判断及局限。类型可用共同失效假设、上下游传播、结构相似、可能互补或冲突；类型帮助解释，不代替是否同 slot 的判断。缺乏证据的组合不强推。

## 规划字段

每个 Slot 包含：`slot_id`、`source_problems`、`target_drawbacks`、`drawback_evidence`、`nearest_neighbors`、`constraints`、`exploration_goal`、`pre_solution_idea`、`slot_path`。另记录 `planning_rationale`、`distinct_direction`、`initial_motivation`、`initial_validation_goal`，用于解释初始边界和追踪目标演化。

在规划输入中 source／target 可使用 Group 稳定 ID；创建时工具解析成完整来源对象并填绝对路径。source_problems 覆盖 target 的来源但不必与 Problem 数量一一对应。允许少量背景 Problem，但不能隐含将它们也设为必须处理的目标。

默认选择少量最有证据和潜力的方向，数量服从独立研究价值、用户时间与可用 Agent／Reviewer 容量。明确哪些初始不足未安排，及其原因（已解决、证据不足、低相关、相互冲突或预算优先级）；这些不是“找不到 Idea 就无价值”的结论。

## 每个Problem的预算

每个选中的Problem必须安排至少十轮有效独立Idea/Review循环。联合Slot仍按实际处理的初始Problem分别计数，背景或被搁置的问题不算完成。先选择尚未完成当前预算的问题，再比较该范围的最高候选；允许聚焦部分drawbacks，但不能据此取消其他目标Problem的预算。Brain可按具体潜力增加轮数，记录涉及Problem、理由及后续验证目标，不重置已用计数。

## 可选预解决思路

仅在证据支持清晰共同 insight 时提供：共同根因假设、核心 insight、可尝试机制、为何可能同时改善、原文证据和尚未成立的假设。文字简短，不能预先铺开完整 proposal、自评分、最低保证成绩或结论式新颖性。

没有足够把握直接 null；不是总控能力不足，也不要求填字段。Subagent 可以采用、改进、否定或完全放弃，按自己的候选比较判断。不要通过 `exploration_goal` 或“必须围绕这个思路”偷偷将可选假设固定。

## 初始来源与后续边界

初始任务记录原Problems／drawbacks、动机、可选假设、硬约束和预期验证目标；机器输入在子目录json，下游用RAW_IDEA.md保留简明只读来源，维护每版候选，不再生成其他Anchor文件。

允许 Claim、机制与目标优先级变化；允许新密切相关不足、只覆盖部分初始目标、放弃预解决思路。关联证据必须足以说明从初始问题到最终问题的关系；数量下降不是失败指标。若已不回应任何原始研究问题，标需要重新定位／停止，不把完全无关的新颖方案算成功。当前循环中目标变化不能清零 Review 次数。
