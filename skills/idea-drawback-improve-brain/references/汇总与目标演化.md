# 单份总结、收集与演化

Group根目录只生成 `实验总结.md`，内容限定为最初输入各Improver的Problems／drawbacks、开放探索目标与可选假设、候选数、真实Reviewer调用与分数、每Problem有效轮次和当前预算、预算增加依据、执行状态、当前目标变化和通过／失败原因。未执行实验就明确说明。不要复制全量文献／候选或另写manifest、ideas、ranking、调度／流程报告。

详细规划、调度、结果、比较和候选快照用于代码交换时存 `json/GROUP_STATE.json`；额外规划／比较JSON也在json目录。孩子的候选、初始记录和Idea只链接，不重复排版。

addressed表示最终或最佳暂定方案声称处理且设计验证，不是实测解决；unresolved是未纳入方案的初始目标，不代表全领域未解决。允许部分覆盖、放弃种子、新相关目标，但必须有证据且仍回应初始范围并守硬约束；偏题或违规不能作为实验就绪推荐。

研究终态必须逐Problem完成当前预算（至少10轮）；候选数量不能代替有效审查。真实工具阻断保持未完成，不能计为研究已结束。总控只读孩子 `json/SLOT_RESULT.json` 和 `json/REVIEW_STATE.json`，核对已有Gate与实际最终文件，不代审、改分或升级失败。执行失败没有合法结果时只记Group状态，不伪造孩子结果。

跨Slot按Claim、实际机制及最小验证判断重合，引用 `(slot_id,candidate_id)`，不同Slot的N001不能自动合并。重复代表必须为真实通过的最终候选，原历史保留；互补机制不能直接拼成未经审查的新Idea。排序以价值、机制、可验证性、复现和完整成本直接判断，不按覆盖量或不同Reviewer分数算总榜。

比较需要落盘时使用模板JSON放Group/json，结论只在唯一总结中简述，不再生成独立排名文档。最终给用户唯一总结路径及真实通过／失败数。
